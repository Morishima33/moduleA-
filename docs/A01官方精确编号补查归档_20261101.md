# A01官方精确编号补查归档

本次接通 `A01.identity_probe.1`：把本版待核HERB关系的精确编号、官方原响应及来源一致性说明归档到对应研究。不采用身份、不排除关系，不生成科研批准或下游运行。已有三库原件和旧研究保持。

## 网页入口

独立预览研究的A01页，在“待核原件与官方响应”之后进入“官方精确编号补查”。先点击“读取补查条件与已归档凭据”，核对本版原编号及已有回执；读取不联网、不提交任务。填写补查登记人、说明，主动勾选后点击“确认补查官方凭据”，由后台按服务端核对出的原编号执行。首次不勾确认；原版本改变须刷新，不自动重交。

历史回执分为凭据完整归档和部分查询失败。展开后显示逐项来源核对结果、逐次查询的HTTP状态、原获取时间、是否复用，并可下载回执和官方原文。失败不记作零条；相同请求明确重试只补未完成查询，原成功响应、获取时间和失败尝试都保留。人工暂存/退回、回收站或版本变化阻断执行；历史回执仍可只读核对。旧服务缺少能力声明时不显示或请求新接口。

## 凭据与科学结果的边界

- 由当前 `A01.system_publication.1`、原三库绑定、方案、HERB成分关系实际行及原命名表定位编号，不接受网页传入编号、URL、路径或通过标记。
- 按原HBTAR编号查询HERB靶点详情；按详情明确Gene/HGNC编号及原候选HGNC编号查询NCBI/HGNC，保留全部候选，不挑第一项。
- 原候选编号兼容归档中的竖线分隔文本和列表。核对每份历史回执实际成功查询的编号，缺少原候选时显示覆盖缺口；保留早期原文，不用较新的查询补写旧回执或冒充旧次已完成。最终凭据按原靶点分别归属，不混入其他靶点的候选。
- HERB和NCBI均指向非人类，只记“来源非人类已查明，未排除”；稳定编号指向一致人类现名，只记“稳定编号一致，未采用”。原名称歧义、冲突、缺编号及失败仍需按已有规则处理。
- 原 `HGNC.resolve.3` 和三库发布算法不改。补查完成不表示原待核已解决，不能直接启动A03或作为科研审核通过。
- 每个请求绑定研究、A01与当前输入指纹；排队后、获取前和发布前重新核对。锁外联网，锁内追加不可变回执；成功重试只读原回执。未完整查询目录和失败原文保留，不覆盖历史。
- 官方端点固定；有限重试临时网关/连接问题，格式或精确编号不符不重试。成功缓存核对URL、原请求体、HTTP状态、长度、SHA和内容结构，损坏不通过重新下载掩盖。
- 原查询、响应、请求绑定、补查实现快照及正式回执带长度和SHA，完整研究追溯包含 `plan_decisions.component_identity_probes`；下载只接受本研究本回执的附件编号及指纹。
