# A01待核原件与官方响应只读核对

系统三库A01结果存在待核项时，原表中的“物种缺失”等说明不足以直接定位原始靶点与查询。同一蛋白还可能出现在多个成分关系中，逐行查找会重复工作。新增`A01.identity_evidence_view.1`，只整理本版原记录及已归档官方请求/响应，保留每条问题和来源。

## 网页入口与操作

独立核查预览19886的A01页，在“本轮需要你核验”之后提供“待核原件与官方响应”。点击“载入本版只读核对清单”，才读取清单；页面载入不自动取证或启动任务。可按来源库、原名或原编号筛选，展开每组查看原问题字段、原查询及原响应候选，再下载同批JSON、逐记录CSV和原件。

这里没有身份确认、排除、整体复核或继续计算按钮。归并查询不等于合并真实基因，响应返回条目数也不等于可采用身份数；仍按原A01和复核状态阻断。旧协议或旧服务缺少能力时保留原页面，不请求新接口。

## 读取与保护

- 只支持当前`A01.system_publication.1`与其已登记`A01.system_source_binding.1`原件。不读其他研究，不从后来原件借数据。
- TCMSP按原表行号回对成分、药味和物种字段，列出原靶点ID/名；对应原查询需URL、payload、长度及SHA一致。缺少原文、HTTP成功空列表和本记录不适用查询分别显示；损坏明确报错。
- HERB/BATMAN保留原符号、候选、source_ref和来源文件，不以名称大小写或相近名称推断物种与基因。
- JSON包含所有核对组和原响应候选字段；CSV每条原问题一行，保留issue_key及原始字段。下载只接受本清单附件编号和版本绑定，拒绝任意路径/URL和版本过期链接，字节读取后再核状态。
- 接口仅使用标准库做读取、分组和显示整理，不联网、不调用科学映射或验证器、不写研究，不改变原件、版本、结果、人工决定或科学门控。科学内核、状态内核及冻结模板保持。

## 实际验证与边界

Windows现有科学解释器完成27项新旧单元/真实HTTP检查；测试数据均在隔离目录，网络为虚构。覆盖原请求关联、重复关系保留、无靶点字段、空响应与缺档区分、损坏拒绝、旧链接拒绝、真实生产发布后的接口回读及原API兼容。

真实资料例另以`-I -S`独立核查：178条原问题整理为45个核对组，含36个不同蛋白查询、6条缺靶点字段记录、3条其他来源身份记录；逐条对照先前原表/官方响应核查，76份登记下载原件指纹一致，CSV仍178行，manifest保持且未导入科学依赖。这是只读证据核查通过，178项待核并未因此自动消失。

网页使用真实浏览器核查宽窄屏、展开原字段与实际下载，检查0 POST、0网页错误和研究归档不变，并核对旧服务隐藏能力；截图、JSON/CSV、原件、日志和研究数据全部留在仓库外`audit_20261029/plan_reports/component_identity_evidence_*`。新前端构建保留旧资源。

本视图只展示A01本版已绑定的原件，不把额外联网补查所得的独立HERB/HGNC/NCBI审计包冒充已经进入科学输入。补充来源证据的正式归档、逐项决定及新版本重算仍须后续接入并验证。疾病旧原件可复用的事实和其数据库版本未知的状态分别保留；本功能不放行缺版本的五库资料，不代表真实全链、双报告或统一验收完成。
