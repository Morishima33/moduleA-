# A01新方案三库发布与标准化

## 本阶段完成内容

新增科学协议`A01.plan_publication.1`，将已实现的OB/DL参数适配接到三库原件、HGNC标准化、结果发布与独立复算。它只处理显式登记`ModuleA.analysis_plan.1`的研究，不修改冻结科学模块、旧固定研究或真实病例。

`AnalysisPlanWorkflow.acquire_analysis_plan_a01_sources(study_id, payload)`只获取和暂存资料，payload明确提供expected_a00、expected_a01、expected_plan_id、expected_staging、databases和reason；`publish_analysis_plan_a01(study_id, payload)`只发布A01，字段相同但不接受databases。调用前核对本研究、当前登记、选定草稿及来源版本，发布过程在原研究写锁中追加运行和结果。

这是后台公开方法集成，尚未新增HTTP启动接口、任务类型或新建参数表单；不能据此宣称全自动研究已经可以运行。草稿校验接口继续返回`execution_available:false`。标准及个性化流程的系统校验、一次执行确认与自动接续仍按大纲后续阶段实施，本阶段不向人工reviews写入“通过”。

## 实际计算与保护

| 环节 | 本阶段实际行为 |
|---|---|
| TCMSP | 获取和最终成分筛选采用同一方案OB/DL；保留原表行号、筛选后成分、排除原因和HGNC映射表 |
| 参数改变 | 发现自动采集门槛与本次筛选不同时阻断；旧默认自动来源也不能直接降门槛后宣称映射齐全 |
| HERB | 原完整成分及已有关系；不附加OB/DL，沿用原64MiB后台完整包及统一stage校验 |
| BATMAN | 原完整成分及known关系；不读预测关系，不附加OB/DL |
| HGNC | 复用原唯一人类身份核对，绑定本研究mapping_file、规则、快照及补充证据；未知身份不自动裁决 |
| 资料完整性 | 三库逐药味核对；缺库不能回退单库，未确认的完整性或关键身份问题仍阻断交接 |
| 运行与历史 | 方案文件、parameter_hash、实际配置、来源及映射文件登记到同一run；追加草稿不会改变旧run复算依据 |
| 获取期间改参数 | 已开始的获取继续使用已绑定草稿；新草稿另存，不替换当前获取的OB/DL。后续新发布须重新明确所选方案 |
| 疾病侧 | 不写入A02，不重新标准化疾病集合，不更改疾病范围或其复核 |
| 导出 | 复用现有JSON追溯与CSV导出，保留三库来源、方案文件、标准化关系和文件SHA-256 |

HERB来源条目的version继续记录原包装器版本，同时另存acquisition_adapter_version和analysis_plan_source。这是复用原包校验的版本分层，不改变HERB筛选或容量限制。原ZIP及查询字节保留。

## 验收方式与边界

本阶段没有新的用户按钮；由助手使用独立虚构研究完成技术验收。用户可核对以下规则和样例结果，无需运行脚本或操作正式项目：

| 虚构样例动作 | 应得到的结果 |
|---|---|
| 默认OB≥30、DL≥0.18 | 原科学表与旧三库协议一致；标准化基因1个 |
| 同输入降为OB≥15、DL≥0.08 | 最终标准化基因3个，包含HGNC:1、HGNC:2、HGNC:3；原件与参数同批 |
| 将TCMSP阈值提高到无合格成分 | TCMSP筛选表为空；HERB/BATMAN保留其已有关系，不能说三库都被ADME筛空 |
| 默认自动采集后直接降阈值发布 | 阻断并要求按新方案补齐TCMSP；不把没补查到的映射解释为零关系 |
| 方案、来源、HGNC或统计被改动 | 指纹或复算拒绝；不发布被拼接的结果 |
| 旧研究、回收站、过期草稿及过期来源 | 拒绝发布；保留旧批和原复核 |

本阶段不访问真实数据库或运行真实研究；真实三库获取能力和网页端到端验收须在创建及任务调度接通后单独执行。隔离测试结果、回归输出和上传日志保存在仓库外开发与验收档案/audit_20261026/plan_a01_publication。

最终A01新增16项集成测试通过；加上原获取、上传、完整性和追溯回归共52项通过。固定第24版模板28文件指纹通过；components.py、normalization.py、workflow.py、storage.py、contracts.py未修改。完整模块回归的实际汇总、跳过原因及本阶段文件指纹另存同一验收目录，不将环境跳过项写为通过。
