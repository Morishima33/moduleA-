# A01 新方案生产任务与网页验收

本阶段接通标准/个性化方案的A01原件获取、三库整理与HGNC标准化，形成“网页明确操作→独立后台任务→科学校验发布→结果回读→等待独立复核”的完整链。新协议为`A01.plan_tasks.1`，科学发布沿用已实现的`A01.plan_publication.1`，不改历史科学算法。

## 页面与操作

隔离预览为 `http://127.0.0.1:19867/`，使用仓库外独立测试数据及运行目录。进入新方案研究的A01页，顶部显示“按本研究方案获取与整理三库”。旧正式服务未替换。预览存活以实际服务为准。

1. 先完成A00登记复核。A01顶部显示当前方案实际OB/DL、缺少的库及不能整理的原因。
2. 选择要获取的TCMSP/HERB/BATMAN，填写依据并主动勾选核对，再点击“按本方案获取所选库”。选择或页面加载本身不发请求。获取只暂存原件，缺库不回退单库；也可在下方按库上传官方原件。
3. 三库原件及共同HGNC依据齐备后，填写依据、主动勾选，再点击“按本方案整理并生成待复核结果”。后台任务面板显示进度、失败和日志；科学计算只在配置的解释器子进程执行。
4. 结果归档后可核查源文件、统一关系、数量、参数与版本、完整性及身份问题。成功不等于批准；问题未决仍阻断。旧自动接续保持关闭，A02及下游不因该任务自动改变。

所有按钮资格由后端提供。历史页/回收站只读；后台忙碌、未通过A00、缺当前方案不能执行。三库不全或缺共同HGNC依据不能整理。发布会再次完整解析和校验科学输入，按钮就绪不代表来源科学核查已通过。

## 版本、失败和恢复

请求严格绑定当前A00、A01、方案草稿及来源清单，不接受客户端参数、路径、评分或批准覆盖。后台启动时再次检查；排队期间绑定过期会拒绝，不能静默改用新草稿。已经开始采集的批次固定原草稿，运行中另存草稿不会改变本批OB/DL。

部分采集失败时任务明确失败，成功库和下载轨迹保留；刷新后按当前绑定仅补取所需库。取消/中断不自动恢复，原件保留，按原任务规则明确重试；旧版本请求过期时从页面重新提交。默认新旧研究不跨研究复用资料，已有采集缓存仍按本研究/A00/A01、药味和相关门槛绑定并核验。

同一方案、同批原件已有当前有效A01时禁止重复发布。新草稿可用同一完整原件重新筛选；若TCMSP原件仅包含高门槛补查靶点，低门槛发布仍拒绝，须按新方案补齐。历史结果不回写，HERB不额外施加OB/DL，BATMAN只使用known。
