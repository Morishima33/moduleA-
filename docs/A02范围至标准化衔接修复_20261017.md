# A02范围保存到整体复核的衔接

本轮于2026-10-17实现，2026-10-19继续完成52项回归、最终构建、本机服务更新和只读网页核查。服务更新前后两个项目manifest指纹完全相同。

用户反馈范围已全部排除、刷新后“通过”仍不可用。核查发现：`A02.collect.2`属于候选收集，固定禁止交接；范围保存正确，但新版网页缺少既有`normalization.preview/publish`的入口，通用阻断说明也没有指出下一步。

新版A02范围表后增加“基因身份核查与标准化”。用户点击核查，后台生成与本研究A00/A01/A02三个版本绑定的预览，显示两侧基因数和完整身份例外。核验人填写依据、明确接受本次身份处理后，调用既有发布入口形成待复核结果；不批准、不启动A03。已有且科学内容未变的已批准A01由原发布逻辑保留。

范围全部排除会显著提示疾病集合为空，按原有有效空结果协议进入整体复核；不自动恢复本病条目、不将候选记录数当作疾病基因数。待核验范围、身份问题未明确处理、输入过期、回收站、忙碌或错疾病来源均不能绕过。预览仅保存在runtime内本项目独立目录，发布重新验证原指纹。历史归档、原候选协议、HGNC规则、评分规则和报告规范均保留。

代码索引：`core/normalization_bridge.py`为版本与预览缓存桥接；`api/server.py`和`api/views.py`登记操作及上下文；`tasks/worker.py`调用原标准化函数；`NormalizationReview.tsx`为前部操作区；`core/status.py`与`presenters/sources.py`准确说明候选阶段所缺步骤。

验证：7项虚构研究回归覆盖空结果开放复核、身份例外、旧输入和跨项目预览拒绝、忙碌及回收站、API版本绑定与已有A01批准保留；隔离浏览器实际执行范围保存、预览、标准化三个后台任务，自动更新到“有效空结果”并开放通过，未新增批准或A03，浏览器无JS错误。生产只更新程序和启动服务，未替用户计算、改变范围或批准。核查证据位于仓库外开发与验收档案/audit_20261017/normalization_bridge。
