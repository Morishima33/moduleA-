# A04身份方案确认与应用

## 页面操作

1. 打开A04，标题下“本轮需要你核验”区默认展开身份清单。
2. 点击“查看证据”，核对输入基因、HGNC编号与STRING返回名称；可以下载同一次运行的原始资料。
3. 点击清单上方“确认补查方案并应用”，或证据窗口中的“确认本项补查方案并应用”。
4. 选择补查项，填写实际核验人、核验说明，并勾选确认；点击“确认方案并应用到A04”。
5. 查看后台任务。成功后页面显示保存人、说明和应用结果；刷新后仍保留。新A04结果另行复核，不自动通过或接续A05/A06。

确认的内容是**补查方案及有限处理范围**，不是宣称全部身份已经核实。程序沿用原有严格证据规则：HGNC官方快照中的全部UniProt／Ensembl稳定编号均需补查；唯一且一致的结果才能采用，原名称返回编号与稳定编号冲突时仍失败。

“同意此项有限处理”默认不选。用户明确勾选后，也只有所有稳定编号请求成功且均无命中，才仅对本次PPI暂不采用；A03交集和富集输入保留。缺编号、请求失败、歧义或冲突不会因此排除，未解决项目继续显示待核验；不会写成Degree=0。

## 保存、版本与失败

人工方案通过IdentityWorkflow公开方法追加至所属研究`decisions/A04_identity/`，manifest只追加文件指纹索引；绑定研究、当前A03与待处理A04。旧上游的授权不继承，新方案不改变旧运行的授权。

A04.identity_apply.1只新增人工方案的归档与读取规则。科学筛选和图表继续复用A04.dual.3：第一轮Degree五列表→第二轮圆形网络图→第二轮BC/CC表；阈值、完整网络指标、排名与并列处理不变。

取证失败或编号反证时：方案、已经返回的补查原文和失败原因留存；页面提供原文下载，旧A04不被覆盖。失败重试复用原人工决定，不重复代签；当前研究或版本已变更时拒绝重试，须刷新重新确认。历史及回收站保持只读。

## 本轮检查

- 49项外壳检查：实际接口提交、必填与人工确认、令牌/Origin保护、跨版本及非法范围拒绝、后台任务等。
- 26项相关科学检查：真实应用生成新A04、独立来源复算、冲突失败、失败原文留存、重试单一决定、空响应的授权区别、归档防篡改与旧筛选回归。
- 浏览器使用独立虚构研究，经真实HTTP和真实后台子进程执行保存与应用，并检查刷新反馈、历史只读、窄屏、错误信息和下载；外部STRING响应在测试中替换为可核对的合成官方格式数据，不向真实研究写入模拟决定。
- 旧PPI历史测试所需固定HGNC原件，仅在独立核查目录提供并注入参考位置；不改变原科学规则，不往正式代码仓库放入数据库。

真实研究的身份问题与人工审批保持原样。技术检查通过不代替研究身份核验或A04验收。

## 大纲增补待用户确认

A04必核事项紧接标题；清单默认展开。查看证据后，可人工确认绑定当前研究、A03、A04的补查及有限处理方案，保存并后台应用至新版本；剩余问题继续阻断，成功结果另行复核。失败原文可核查，历史不覆盖、不代签。

同一A03的逐项补查保留已应用的人工范围，新选择追加；决定记录引用原已应用方案，旧运行继续按原决定独立复算。再次计算A04沿用当前结果已绑定的同上游方案，不重复签署；更换A03不继承。
