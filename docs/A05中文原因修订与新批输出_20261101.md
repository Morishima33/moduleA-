# A05中文原因修订与新批输出

真实流程自检发现，Windows固定R环境中的第一版脚本把未纳入条目的中文原因写成控制字符。四个检验族的背景、命中、原始P值、BH校正和显著集合已单独核对；文字损坏仍属于需要修复的输出问题，不能以统计正确代替交付完整。

独立 `A05.plan_enrichment.2` 使用 `plan_enrichment_utf8.R`，只将原脚本三个中文字符串常量转为R的Unicode转义。原 `plan_flow.py`、`plan_enrichment.R`、`plan_contract.py` 及固定科学内核保留。新适配器复用第一版的统计函数代码，在独立命名空间绑定新脚本，不改变旧模块全局值；配置指纹同时覆盖新旧实现和文字修订桥接。新旧结果比较只允许协议号、归档表行索引和损坏的中文原因不同，其余全部统计必须保持。

新明确可恢复批次固定 `enrichment_protocol=A05.plan_enrichment.2`，原批无字段继续原协议；重试旧批不自动升级。已有第一版结果可以通过公开 `Workflow.revise_analysis_plan_a05_text(study_id, request)` 显式修订，后台任务为 `plan_a05_text_revision`，沿原全局资源预算、磁盘检查、进程树管理和取消规则。该技术修订不联网，不引入新的科学阈值，也不签署人工复核。

请求严格包含 `request_id`、`expected_a05`、`expected_input_hash`、`author`、`note`、`confirmed`。当前来源必须是同批有效的第一版系统A05；方案、交集、原件和人工意见发生变化、回收站或真实科学阻断均拒绝。登记的请求及实现快照不可变，每次尝试独立保存脚本与R日志。新版本经过实际R复算、原统计逐项比较及生产规范复算后才追加发布；相同已发布请求返回原修订，失败和旧原件保持。

第二版统计使用独立 `A05.plan_display.2`、`A05.plan_display_source.2` 读取相同分类和词典规则。原第一版展示文件冻结；新适配器明确区分统计、展示决定及最终人工复核。完整追溯保留文字修订请求、回执、失败和原统计；新A07报告使用与本版统计匹配的来源快照。旧报告和28件冻结模板不修改。

当前入口属于后台技术修订，没有新增专用网页按钮。模块页沿用现有A05结果展示及展示资料入口，当前部署、真实修订发布、双报告和目视验收状态以仓库外本轮核查记录为准，不能把代码已实现或合成测试通过称作用户已验收。

已有隔离验证覆盖新旧实际R对照、同批公开修订、真实后台任务、幂等、人工暂停、R失败、伪输出拒绝及新批协议绑定。另对当前实际规模的1824基因离线复算，14598条中文原因恢复，全部统计表及除协议号外摘要一致；该次离线产物没有替换研究当前结果。后续完整集成、失败恢复原件保存、第二版展示/报告和真实发布需分别记录实际结果；日志及研究原文不放入代码仓库。
