# A06 人工整体复核接入

新增 `A06.plan_reviewable_preparation.1`，将新版同批准备从“资料可核对但无法整体通过”接到现有人工模块复核。原参考准备版本、科学规则、原件、失败记录和已有复核保持；状态及存储内核 `workflow.py/storage.py/contracts.py` 未修改。

## 操作与范围

在新版 A06_PREP 页的“进入人工整体复核”区，资料完整、上游与独立选择复核有效、固定输入匹配且至少有一个 ready 组合时，允许展开资料复验表单。填写复验人与依据并主动确认，只生成一个后台复验任务。首次不确认、不选择通过。

科学子进程从固定的第二版参考准备重新验核全部科学证据，追加独立准备运行。固定成分、受体、组合顺序、ready/NA及空评分原样保留；新结果设置 `reviewable:true`、`handoff_blocked:false`、`scored_pairs:0`、`execution_available:false`。这只开放人工整体复核，不自动提交科研批准。

任务完成后，使用原有“复核决定”表单，人工选择通过、退回或暂存并填写意见，点击“仅保存复核决定”。通过和撤回均留在既有 reviews 历史里；程序不会预选通过。独立受体选择复核撤回、上游变化、固定准备输入变化后，新准备与普通批准一同失效。

全 NA 不生成可复核准备。不存在可用组合时必须修复对应资料并重新准备，不能填零、补其他排名对象或伪造评分。网页显示归档成功与正式人工批准为两个步骤。

## 执行隔离

新版正式评分执行器仍未实现，评分预检和闸门继续返回 false。页面隐藏旧自动计算区并禁用“保存并继续”；保存请求即使伪造 `after:continue` 也只保存人工决定。手动 continue、后台 continue 及 Workflow 的 A06 创建入口共同阻止调用旧评分协议。该隔离仅作用于此新增版本，旧版本按原逻辑工作。

GET/POST `/api/v1/studies/{sid}/analysis-plan/a06-reviewable-preparation` 的完整字段见 API 契约。请求带固定准备、输入、请求编号、复验人、依据和明确确认。重复请求同编号同内容回读原归档；改内容、过期版本、损坏来源、回收站或已失效上游拒绝。HTTP 进程只做标准库核验，科学复算在后台进行。

## 验收证据及边界

专项测试覆盖真实生产入口复算、原准备不变、人工明确通过及撤回、幂等和冲突、非法字段、源文件损坏、矩阵篡改、跨路径、上游撤回、独立选择复核撤回、回收站、全NA及旧评分隔离。合并评分预检与模块导航测试一并执行，最终结果见重构根 `开发与验收档案/audit_20261028/reviewable_preparation/upload_check.json`。

浏览器实际操作与截图保存在同目录 `browser_check.json`、`reviewable_1440.png`、`reviewable_390.png`。浏览器夹具上游、结构和预测为合成，配体参数化及证据校验实际执行；成功路径为固定4组合、ready=1、NA=3、评分=0。真实网页提交科学子进程后，不自动新增 reviews；人工表单明确选择通过并保存，随后更改为暂存，评分始终关闭。该验证只证明技术链路，不代表正式疾病研究或真实批量评分验收。首次脚本地址计数错误及服务重启后会话重试的诊断保留，最终验证以通过的汇总为准。

下一项是新增正式评分协议与后台执行器，绑定本版本的明确人工批准、原参数、固定组合及构型，执行前后重新核验；尚不能将本次人工复核接入计为该评分任务完成。
