# A06双语展示修订与名称证据

## 问题与边界

已有救援评分的固定输入可以只有英文名称。准备包中的`name_zh`也可能只是原英文，
不能仅凭该字段非空声称中文核译完成。旧`compound_names`依赖其他流程的复核记录，
不能以当前A03兜底代替本批固定父来源。

沿用用户已批准的基础层计划，只追加绑定本运行的展示修订。原科学packet、固定输入、
评分、构象、顺序、NA、人工意见、历史图件和Word保持；不增加科学豁免或生成Word。
运行中的冻结科学实现和实际服务保持，实际修订须在完整结果登记且无活动任务后发表。

## 名称证据

准备成功对象按本批归档CID、原名、准备及来源证据指纹核名，保留每个稳定成分ID；
相同CID或中文名不合并来源行。缩写不能单独用于身份推断。

未准备成功对象的译名单列`scope=source_term_translation_only`，只表达原来源术语，
绑定原HERB稳定ID、精确原名及同批来源证据。原来源声明的CID不得当作已核结构身份。
网页、图、CSV、目录均保留原名和身份未核／NA原因，术语核译不改变可评分状态。

词典每项保存稳定外部编号、原名匹配条件、中文、来源链接及人工核译依据。
只有英文的`name_zh`、占位文字、冲突、缺译或证据不足阻断交付。
原名、结构身份确认和中文术语翻译分别记录，不能用一个“已核实”概括三者。

## 独立修订归档

新增独立展示账本，精确绑定原A06的run/result/scoring packet/input及原PREP、A03引用，
并固定名称证据、实现和同次导出尝试。通过公开Workflow追加，不写入原`result.files`。
发表前再次核来源、人工决定和当前任务条件；不重写状态、存储或队列内核。

复用既有二版矩阵几何、色标、CSV、PNG/SVG与MODEL 1下载。新的展示构造器从已验证原包
派生双语标签，不替换`source_fixed`后冒充原科学包。
每个修订单独保存名称证据、展示JSON、完整／焦点PNG/SVG和完整CSV。

网页、焦点读取、图件、CSV、验收包显式选择同一个修订ID和SHA。
旧附件继续可追溯；修订文件与科学结果原件在ZIP目录中分列，各自保留登记关系。
旧下载链接不能在后来修订发表后静默指向新文件；输入、修订或字节绑定变化拒绝。
GET只核验和读取，不能补图、发表或提交科研复核。

## 实施与验证顺序

1. 先补英文假中文、占位文字、缺译等交付门控反例。
2. 建立有来源的名称目录和独立展示构造器，核稳定ID、原名、CID／HERB证据。
3. 接公开Workflow的独立准备／发表、实际任务预算和同研究单任务规则，短锁追加账本。
4. 接只读网页、焦点、图／CSV下载和ZIP，所有入口绑定同一个修订。
5. 检查同名不合并、错CID／HERB／原名、换源、退回、缺译、旧链接及并发发表负例。
6. 逐格比较评分／状态／顺序／NA原因、原MODEL 1字节和全部原登记文件保持。
7. 在隔离合成材料和实际来源只读预检通过、独立复审后按精确清单上传。
8. 实际A06完整发表后才正常部署并追加本批修订，核用户8780入口和真实下载。
