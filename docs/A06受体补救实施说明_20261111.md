# 同批原失败受体补救

`A06.system_rescue.1`沿当前已批准的原A06_PREP来源，针对其中准备不可用的受体追加独立A06结果。原名单、顺序、配体准备、Vina参数及已有有效评分保持；原评分的实际执行记录只读沿用，新区域评分单独归档。未准备成功的配体继续保留NA及原因，不替换成分或填零。

准备路线复用旧版完整分页、唯一人类稳定蛋白编号和实际序列核验、独立实验结构及有限侧链补全，再使用已发布模型。禁止重建主链或长环、改变原重原子坐标、丢弃必要伙伴和金属。预测模型逐区域检查平均pLDDT≥80、最低≥70、双向PAE≤10Å。完整映射预测口袋在评分前固定，无可映射口袋时才采用原30Å盒、15Å步长、外围5Å的分区；工具执行失败保留诊断。每个受体的所有成分使用同一结构与区域集合，保留各区域Top-1及无效原因，按原规则选择有效区域最低评分，结果明确标注探索用途。

## 执行与恢复

准备页点击“受体补救与补算”后才读取`GET /api/v1/studies/{study}/analysis-plan/receptor-rescue`。显示当前来源、缺项及可恢复状态；明确填写登记依据并确认后，`POST .../execute`提交严格七字段：`request_id`、`expected_preparation_run_id`、`expected_scoring_run_id`、`expected_input_hash`、`author`、`note`、`confirmed:true`。不接收路径、名单或参数覆盖；包括空值在内的额外查询参数均拒绝。

沿既有单研究重任务队列及资源预算执行；已登记的成功受体及区域评分只核验复用。明确暂时错误可追加下一次尝试；普通失败保留原件和原因。同一请求不能变更配置、工具、实际实现或人工决定。更正技术实现时须使用新明确请求，旧未完成运行、检查点及失败档案保留。发表中断只恢复已登记且逐字节匹配的候选，不以目录中孤立结果冒充完成。

本批复制Vina及代码快照，绑定本机实际Python、Java、P2Rank默认模型、依赖和修补包字节。只在科学子进程设置定位出的现有`JAVA_HOME`；不改全局或安装软件。区域评分验证当前复制Vina、命令、原子身份、搜索盒及第一模式；准备、恢复与最终发表完整核验准备依赖。出图每次使用独立尝试目录，部分图件保留且不会阻塞有效评分恢复。

## 结果与复核

A06展示完整固定矩阵、仅有效对象的焦点图、受体补救事实、原有效评分数/新增数/NA及失败数。焦点图是显示范围，完整CSV及PNG/SVG保留全部固定记录，同名成分以来源ID区分。各组合的NA使用同一事实原因，Top-1下载逐字节对应实际计分第一模式，不能拼接其他组合或历史批次。

新结果待独立人工复核，旧PREP批准不冒充补救结果已审。原报告、用户批注和历史统计不覆盖，未经要求不生成新Word。旧A07可作为历史查看；使用新评分的报告须按新批次另行生成。源代码技术自检、真实研究运行、网页实际检查、GitHub上传和用户验收分别登记，不用一项代替其他项。
