# A06扩展名单至自动执行接续

本次修复运算入口对旧版扩展筛查流程的接续，区别于之前仅恢复完整大表展示的修改。用户已明确本次COPD采用15个成分、受体保留第十五位边界并列，共16个受体，目标240组。当前80组及全部研究批准保持，不在本次代码修复中启动真实计算。

## 已确认的原因

鼻炎阶段的`intersection_flow.py`、`trial_rules.py`、`trial_compute.py`仍保留原字节，并已上传。新自动路线读取本研究已批准的A03_SELECT对象，但之前没有区分默认前五主候选和完整扩展名单，导致COPD以默认5项继续形成80组合。旧15项补充选择代码仍在，遗漏的是新入口的名单草稿、范围检查及换名单后的接续。

## 修改后的实际调用

1. A03_SELECT从本研究当前A03生成扩展草稿，前五主候选排序保持。默认建议前15个有交集关系的成分，并列完整列出；已归档的身份待补项不能进入草稿。可用对象不足15时如实列出实际范围，不伪造名额。
2. 点击“载入前15项扩展筛查草稿”，在前部直接显示全部名单、来源药味、原名次及逐项补充依据。载入只改本地草稿，不自动勾选身份确认、保存、批准或计算。
3. 用户核对后保存。仍调用原`intersection_flow.run_selection`及`select_build`；有明确补充依据时仍产生A03.select.4，保留原主排序、选择角色和来源，未另写一套选择算法。保存后仍需独立复核。已保存的逐项补充理由从本研究原结果回读，刷新后仍保留，不会清空并退回默认规则。
4. 新第三版连接入口、后台连接任务及新执行授权再次核对完整范围；在本研究有足够候选时，默认五项不得当作完整扩展范围开始新计算。原一、二版及已登记第三版授权继续按原版本追溯。
5. 范围通过后，仍由原`plan_adapter.source_context`读取全部已选项，受体仍由原A04候选规则保留边界并列。本次实际投影为15×16，240个唯一组合，无前五截断。
6. 更换名单使旧A06失效时，首页和研究页的下一步先指向完整名单核查；范围通过后，点击接续会指向A06_PREP连接与一次执行确认，不再要求复核已失效的旧批次。旧批次、旧评分及批准记录保留；新连接与执行不继承旧授权。

`A06.extended_scope.1`只标识上述入口检查和草稿。没有修改冻结选择内核、Vina参数、80/70/10置信度、重对接RMSD门槛或已有科学协议的评分解释。
