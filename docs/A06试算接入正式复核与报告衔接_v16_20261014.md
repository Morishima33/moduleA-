# A06试算接入正式复核与报告衔接

本轮修复“试算核查已确认，但正式A06仍不能通过”的流程问题。新增扩展试算结果版本，引用已完成的评分，保留严格准备和失败历史。试算核查不再与正式复核入口混淆。

## 页面操作

1. 在当前研究进入 **A06分子对接**，顶部显示“当前A06复核：225组合扩展试算结果”。
2. 点击“定位正式复核按钮”，在复核栏选择“通过，允许下游使用”。核验人和意见可沿用已确认的试算核查，决定不预选。
3. “仅保存复核决定”只保存；“保存并继续”保存后生成新双报告，并停在A07等待独立复核。报告直接引用本批评分，不重新对接。

A06_PREP保留严格准备状态，显示“前往本批A06结果复核”。无需重新勾选成分或逐项重做已完成的试算核查。

## 版本与用途

- 新结果协议 `A06.trial.handoff.1`，绑定当前已批准的A03、A03_SELECT、A04、本批试算及其最新明确确认记录。
- 新结果生成时不批准A06；试算核查人与说明仅预填，正式决定仍由用户提交。原A06_PREP、历史A06和人工记录保持。
- 用途为扩展筛查与报告，不表示全部受体严格质控通过，不改写旧RMSD失败或结构质控等级。
- 上游、试算输入或核查记录改变时，旧交接结果失效；历史页面及回收站保持只读。
- 新双报告采用第21版适配。专业版A06包含同批8×8红蓝热图、15×15横向矩阵及受体处理说明；原始评分≤−8的格附“**”，不表示统计显著性。临床简报保留重点8×8图，不指定未经验证的“主要五受体”或最高药效组合。
- 报告摘要与研究线索引用已确认的A04、A05展示范围；已排除的疾病条目仅在排除审计说明中留存。新报告不覆盖旧报告，A07独立复核不自动通过。

## 验证与边界

在真实资料的隔离副本中实际执行正式按钮保存、刷新及报告生成；专业版14页、临床版2页逐页渲染检查。新协议5项回归通过，另有既有试算12项检查；前端类型检查、构建及实际浏览器操作通过。详细截图、日志和原件指纹核对保留在仓库外的本轮核查目录，研究资料不上传GitHub。

正式研究仅新增待用户复核的A06扩展结果；技术自测不代签实际研究。原项目、既有225评分、540区域输出、成分名单及A/B分组保持。
