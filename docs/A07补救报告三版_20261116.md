# A07 补救报告三版

新明确版本 A07.plan_report.3 / plan_payload.3 / plan_documents.3 / plan_figures.3 支持 A06.system_rescue.1 和 .2。对应旧运行仍使用其原科学 validator；不把补救伪装成 system_execution，不改变名单、参数、评分、准备批准或人工复核。

## 来源与发布

后台从本研究当前完整父链构造事实，补救评分调用对应生产 validate_packet，读取完整评分包；平面表不能替代准备、区域、实际命令或 Top-1 证据。完整矩阵保持原序、原分数及 NA/失败原因。沿用与新增组合数、未成功区域记录、探索限制明确分列；区域次数不称组合数。

展示对象不复制大型 attempts 字段。完整原包、来源和准备尝试仍通过原 scoring_packet 指纹引用保留，原对象不改；各组合的 regions、执行、原始姿势及 Top-1 引用完整保持。

正文继续原二版图形、稳定ID核译与第24版排版，Degree第二轮与全网概览分开，矩阵使用实际名称。未成功区域表显示实际名称、稳定ID及原原因，独立回读逐行核对，不允许跨对象交换原因。实现快照和图件来源另存，历史一、二版文件字节保持。

公开发布只经 Workflow 的 publish_analysis_plan_rescue_report；begin、发布前及结果生产 validator 仍完整重建事实、核对科学规范、当前系统回执及真实依赖。结果等待独立科研复核，不自动签署。

## 只读页面

状态有效性使用 checked_inputs_archive：核已登记明确请求、payload 原 SHA、完整科学 binding、所有当前父链、实际系统回执、完成状态、图件 payload_hash、全部附件及实现 SHA，并核 run 的配置、父 artifact/validation 和输入指纹。使用标准库分块核文件；不以 TTL 或时间戳冒充 SHA，不在 GET 导入科学/Word依赖或重新执行科学工厂。

此只读路径不能用于生产结果放行。后台 checked_inputs、validate_result 和已登记生产 validator 保持严格科学事实重建；缺译、未完成、来源变化或人工退回仍阻断。

## 协议兼容

原报告 GET / generate / files 地址保持。当前补救评分或已有三版报告选择三版；history 和下载各按原三协议登记读取。新明确排队请求固定 report_protocol=A07.plan_report.3，旧扁平任务仍一版、旧 .2 任务仍二版。未新增GET写入、自动生成或默认科研批准。追溯导出增加 report_rescue_requests / receipts / failures。

## 实际验证与限制

- 初轮旧报告、HTTP、原补救内核等 47 项回归通过447.265秒；之后独立复审发现状态读取进入科学工厂的问题。
- 该问题先在无科学依赖的 -I -S 子进程中失败复现，修复后通过。大型 attempts 的展示复制也有红绿复现。
- 修复后的三版12项通过121.630秒，另实际本机HTTP三版GET、下载SHA和POST队列协议测试通过33.274秒；合计13个不同用例。覆盖源退回、payload/回执/图件变字节失效、旧附件保全、标准库读取和非空补救合同。
- 独立审查原P1已复审关闭，未发现新增Important；审查者未重复执行上述测试，测试结果以原机日志为准。
- 非空补救测试对生产validator使用明确合成替身；实际生产发布验证为合法空研究。不能据此称真实COPD完整非空补救已通过。真实评分完成后仍须另核全包、图表、网页、下载与用户科研验收。
- 本次只修改代码并在临时合成目录测试；未生成新的真实研究Word，未覆盖历史报告及批注，未安装依赖。
