# GitHub 自动上传说明 v1.0

## 给项目负责人的说明

每完成一个模块并通过相应检查，助手会自动提交并上传到 `development`，并提供提交链接、改动说明和验证结果。你仍负责核查模块和确认大纲；不会自动合并到 `main`。

无需安装 GitHub CLI、后台服务或定时任务。使用现有 Git 凭据管理器；认证过期时在登录界面重新授权，不在代码、JSON 或聊天里粘贴密钥。

## 上传什么

上传源码、前端构建产物、测试、项目说明、大纲、模板、启动脚本及配置样例。依赖锁文件保留；`node_modules` 不上传。真实研究、来源快照、环境工具、个人配置、科研报告结果、截图、日志和核查产物留在本地。

初始基线来源：`Morishima33/moduleA` 的 `docs/architecture-redesign-v1`，提交 `d2c1ee68483142b8e69a11c63ade1228ed4b5609`。新仓库从独立初始提交开始；没有沿用旧 `.git` 或旧 LFS 历史。模板和项目大纲复制的是实际文件，不是 LFS 指针。

## 助手每完成一块时怎么操作

1. 保持在 `development`，列出本次新增、修改、删除的文件，相应检查必须真实执行并通过。初始阶段仍使用 `src/` 和 `web/`，不为了上传重新排列科学代码。
2. 在代码仓库外的独立核查目录保存两份 UTF-8 JSON：检查报告和上传请求。检查报告中的文件摘要必须来自检查后的实际文件；检查后再改文件时，需要重新检查和生成摘要。
3. 执行下面命令。脚本会核对远端、分支、路径范围、检查结果、文件摘要和已有暂存内容；只提交本次清单，推送后核对远端提交号。

```powershell
pwsh -NoProfile -File ./tools/github_upload.ps1 -RequestFile <仓库外的上传请求.json>
```

检查报告格式（示例中的摘要和通过状态必须用真实检查结果替换）：

```json
{
  "schema_version": 1,
  "module": "A01",
  "passed": true,
  "checks": [{"name": "本次相应检查", "passed": true, "exit_code": 0}],
  "files": [{"path": "src/example.py", "sha256": "实际文件的SHA-256"}]
}
```

上传请求格式：

```json
{
  "module": "A01",
  "message": "说明本次完成的具体内容",
  "paths": ["src/example.py"],
  "check_report": "D:/codex-重大专项/moduleA重构/audit_20261009/本次检查报告.json"
}
```

删除文件在检查报告中写 `{"path":"相对路径","deleted":true}`。`paths` 也支持明确的模块目录，但该目录本次变化的全部文件都必须有检查记录；不能用 `.`、上级目录或通配符扩大范围。

## 失败与重试

- 无变化且没有待推送提交：返回 `no_changes`，不产生空提交。
- 检查失败、摘要不匹配、范围外文件或已有暂存内容：停止并保留本地状态。
- 网络或权限导致推送失败：本地提交保留。解决问题后用同一请求重试，不重复产生提交。
- 远端出现新提交或分歧：停止并报告。不能强制推送，也不自动拉取合并、变基或替用户选择冲突结果。
- 日志保存在代码目录外的 `runtime/github-upload/`。日志只保留模块、文件、检查状态和提交号，不保存凭据或认证工具错误输出。

## 本轮验证与限制

上传工具测试使用本地临时仓库和本地 bare 远端，测试数据不推送到 GitHub。验证文件范围、无修改、检查失败、检查后内容变化、已有暂存、推送失败重试、远端变化和遗留提交历史。

上传成功只证明这批文件和提交已保存到 GitHub，不证明科学模块、真实科研全流程或大纲已获验收。本次没有迁入本机三库代码，也没有修复源分支的五项已知问题；部分依赖真实资料的旧测试在纯代码仓库中不能完整运行。
