# HERB下载重试与断点恢复

## 原因与修复范围

本次真实资料在成分详情HBIN049119处连续502，旧实现只试两次且间隔约0.5秒。先前736份成功响应已保留，但重新发起采集会新建目录，没有接上这些断点。修复后真实补取已越过该位置，718个去重成分详情取齐；继而发现完整ZIP超过人工上传16MiB上限，自动归档也被误拦截。

本轮只改来源传输、包装和进度；不改科学筛选、名单、疾病侧、身份规则及复核，不将TCMSP“杏仁”自动替换为“苦杏仁”。

## 当前行为

1. HERB临时408/429/500/502/503/504、超时、连接中断和非JSON网关页最多五次尝试，间隔按2/4/8/16秒递增；数字Retry-After被采用但最多等60秒。404和科研校验失败不作为临时网络问题重试。
2. 逐次留存错误原文及原响应，HTTP 200的HTML错误页不写入成功缓存。实际内容仍须原有字段、编号、全量和身份校验通过，不以网络重试掩盖结构变化。
3. 采集目录绑定本研究、A00/A01及药味。再次明确获取时，可恢复相同绑定的旧成功响应；旧目录需有采集结束记录佐证。每份按URL/请求内容、长度及SHA校验，复制后保留原获取日期与来源尝试编号；不覆盖旧目录。
4. 跨研究/输入改变/药味改变/路径越界不复用；损坏原件明确拒绝。仅同A00的旧记录缺herbs时可恢复，药味仍以同一已核验A00为准。
5. 后台HERB包上限64MiB，通过原stage校验后归档；网页上传仍16MiB，5000成员、256MiB展开量、路径/重复/加密/链接检查保持。客户端来源字段不能启用后台容量；超限仍明确失败，不删原件或截断成分。
6. 自动接续和手动采集任务均报告成分详情序号、总量、已复用原件数及退避重试，日志同步刷新。只有用户明确提交采集才续取，GET或服务启动不联网。

## 验证

新增`tests/test_herb_resume.py`使用虚构请求验证瞬时502恢复、永久404、Retry-After、HTML错误页、有界失败、同绑定恢复/跨研究拒绝/指纹篡改拒绝，以及大包只能走后端容量且原stage保持A02和复核。回归原A01采集、三库门控、上传及API。

Windows项目解释器运行新增12项、原采集7项、三库8项、上传11项、API11项，共49项通过；冻结第24版28文件检查通过。未改科研筛选或对接算法，因此不重新运行真实富集、对接或生成报告。

真实补取：复用原736份响应、补齐718个去重成分详情；最终33.36MiB压缩包通过统一stage，2203份包内文件逐件指纹核验通过。四味药完整原始成分清单为麻黄485、桂枝268、杏仁45、炙甘草17，各药味有重叠，不能直接相加作为去重成分数。该数量是来源清单，不是筛选后或对接成分数。后台最终归档尝试约33.6秒，之前因容量失败的尝试仍留存，不将其改写为成功。

研究当前运行及复核记录完全相同，A02和已有BATMAN暂存未变，另外三项研究索引指纹未变。仅HERB来源暂存增加新版本，未整理新A01、未批准或启动下游；TCMSP药味身份问题仍待处理，不声称三库已全部通过。

真实研究只补HERB，保留原下载及失败任务，不整理A01或启动下游。实际任务、完整性数量、来源指纹对照及人工复核保护证据在仓库外`开发与验收档案/audit_20261023/herb_recovery/`，不上传研究资料或个人配置。HERB外部站点长期故障仍会使补取暂不能完成，后续明确重试可从校验后的断点继续。
