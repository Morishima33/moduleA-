# UniProt临时传输错误与原件恢复

真实三库采集的TCMSP靶点补查曾在不同蛋白名遇到UniProt HTTP 500。原传输器仅立即尝试两次，后续补取虽能复用成功请求，仍可能在另一个查询中断。本次限定修复官方HTTPS GET `/uniprotkb/search` 的临时传输重试，策略标识 `A01.uniprot_transport.1`。

## 处理方式

- HTTP 429、500、502、503、504，超时、连接中断和不完整读取，最多五次尝试。退避为2、4、8、16秒；数字Retry-After可延长等待，单次最多60秒。原每次请求前0.5秒间隔及25秒连接超时保留。
- 每次失败的原文及独立诊断保留；诊断记录尝试次序、HTTP状态、策略版本、是否再试及等待秒数。不完整读取保留已经收到的部分字节。达到上限仍失败，不生成成功缓存或零结果。
- 400/401/403/404/422、证书、身份、格式、重定向主机和响应长度错误不按临时连接问题反复请求。其他来源及原HERB策略保持。
- 同研究同请求的成功缓存仍核对URL、payload、字节长度和SHA-256后直接复用；损坏则阻断。旧成功索引不回写策略、日期或新元数据。

精确蛋白名、人类9606、reviewed:true和唯一映射算法保持原实现；不改OB/DL、药味、数据库完整性、HGNC、来源绑定、运行或人工复核。`workflow.py`、`storage.py`、`contracts.py`和冻结模板未修改。
