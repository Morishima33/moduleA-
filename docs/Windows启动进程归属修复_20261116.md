# Windows 启动进程归属修复

基线 fa3777ef2d3afcbb686d5acfb06d1fde746767ca。本批修跨平台启动器的 Windows 虚拟环境 PID 误判，不改变科学执行、参数、解释器、服务身份协议或停止方式。

## 缺陷与处理

Windows 虚拟环境的 Popen.pid 是启动器，health.pid 是真正 Python 服务子进程。原启动器把两者强制判为相同，实际目录、代码、前端和端口均匹配也返回 instance_changed。

保留 probe_service 原完整身份核验，再记录本次 Popen 进程的操作系统出生标识。同 PID 仍须出生不变且 Popen 仍活着；仅 Windows 允许经只读 Toolhelp 快照证明的直接子进程，其出生不早于父进程，父、子出生均在查询后重核。未知、已退出、PID 复用、非子关系或查询异常一律拒绝。不停止未知实例，不改权限，不替换为另一个解释器。POSIX 继续只允许原直接 PID，未据 Windows 测试宣称 Mac 实测通过。

API 结构与句柄规则依据微软公开 [PROCESSENTRY32W](https://learn.microsoft.com/en-us/windows/win32/api/tlhelp32/ns-tlhelp32-processentry32w)、[CreateToolhelp32Snapshot](https://learn.microsoft.com/en-us/windows/win32/api/tlhelp32/nf-tlhelp32-createtoolhelp32snapshot)、[Process32FirstW](https://learn.microsoft.com/en-us/windows/win32/api/tlhelp32/nf-tlhelp32-process32firstw)。仅查询进程父链，快照均在 finally 中关闭。

原长路径测试的两个目录段带末尾空格，普通 Win32 路径语义会裁去空格，导致七项测试在夹具阶段失败。本次去除段末空格，保留中文和内部空格；临时根较短时补合法目录段，明确断言完整数据路径超过260字符。

## 实际核验

- Windows AMD64 / Python3.13.1，先执行11项：4项缺失守卫和1项真实实例误判，共5失败，原日志保留。
- 修复后同11项通过29.027秒。实际随机端口服务完成启动、重复复用、状态查询、明确认证停止和端口释放；数据目录没有产生 studies，不操作真实8780或补算进程。
- 完整核心入口执行164项，163通过、0失败、0错误、1权限跳过，277.846秒。跳过仅为当前账户无法创建原生符号链接；未更改系统权限，不称所有平台能力已验证。
- 独立只读审查未发现 Important。按 Minor 建议补子进程末次出生变化/消失、未知父链和Toolhelp异常拒绝；最终9项归属专项通过0.186秒。专项与164项有重合，不相加冒充一次全套执行。
- 未知归属或启动期间代码/目录变化时不打开浏览器、不停止对方实例。旧服务认证、预算任务、取消与历史恢复检查均沿原核心回归验证。

原机仓库外日志 windows_launcher_red.log、windows_launcher_green.log、windows_launcher_guards_final.log、windows_core_fixed.log。真实补算在另一冻结副本继续，原数据、名单及科学规则不改；本批不是完整真实研究或网页最终验收。

复验：`python tools/run_core_checks.py`；专项：`python -m unittest tests.modulea.test_launch_identity tests.modulea.test_platform_launcher -v`。两者使用隔离测试数据和随机端口；Mac 科学工具与原 Windows 批次恢复仍须分别核实。
