# WorkerIO.2：显式有界读取候选

本批新增 `ModuleA.science_worker_io.2`，不改变已归档 WorkerIO.1、科学代码、原名单、阈值、状态或存储。它仍使用原 TaskManager、同研究单任务、重任务预算和整树取消。未合并部署、未在真实研究登记二版，不表示整批评分已完成。

## 边界

- 仅精确白名单 source_binding（含原私有入口）、validate_request 和两版 _active 建立纯读取范围；不包裹科学写入、检查点发表或 _finish。
- 首次完整 SHA，范围退出前再次完整 SHA、逻辑路径和 manifest 核验；相同大小且恢复 mtime 的内容篡改仍阻断。跨线程和跨调用不能借用证明。
- JSON marshal 缓存总计最多64MiB，单文档最多16MiB；更大的准备尝试只解析不缓存。绑定结果另限2MiB，每次返回独立容器。异常或正常退出均释放。临时 Workflow 用弱引用身份令牌，不能因 Python 重用 id 而共享绑定，也不保留废弃实例。
- 新任务类型 `plan_rescue_worker_io_v2`，payload 精确为 `{request: 原七字段, run_id, adapter_version: ModuleA.science_worker_io.2}`。旧任务 handler 和旧适配登记保持。
- 新工具 `tools/run_scoped_rescue_worker.py` 分 inspect/resume/execute；inspect不写研究、不评分，resume沿原队列。execute只接受原预算worker及对应任务、实际进程身份/Job归属和完整payload；不能直接启动并发评分。
- 只有显式登记当前未完成的原 A06.system_rescue.2 请求才能科学写入。快照涵盖19件实际参与实现；激活及写前核研究、当前run、请求、config、human_review_written=False、完整无重复文件清单、归档/当前代码指纹。不能用空快照、旧协议或其他运行冒充。登记失败不留下已激活状态。

## 当前证据与限制

原机审计保存在仓库外 `开发与验收档案/audit_20261115/github_review`，不上传研究原件、环境或本机配置。

16项首次缓存/隔离/预算测试通过62.235秒。登记新增红测先揭示7项不完整或错绑定可放行，已补完整核验；后续完整结果以 scoped_full_regression.log、scoped_compatibility.log 和最终审计为准。首轮回归模块名误写为不存在的 test_rescue_worker_io，24个实际用例通过，另1个加载错误；不能称该轮全绿。

真实同一七字段请求只读对照：旧实现一次176.964秒；二版两次145.174/145.794秒通过原绑定、run和reviews相同核对。64MiB方案首次/退出各14379件、各2,282,393,031字节；128864次重复引用在范围内复用；JSON92次解析、343次缓存命中、峰值67,108,424字节。绑定缓存本次命中0、存储4，不能宣称实际复用了绑定结果。另一次遇正常计算追加 manifest，正确拒绝预检，保留失败日志。
