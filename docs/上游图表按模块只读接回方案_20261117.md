# 上游图表按模块只读接回

## 已确认问题和边界

实际8780展示资格GET返回supported=false、current=null，原因为当前A06未完整归档。
已有两份展示修订仍在；A03/A04/A05的原科学运行未改变，但整包来源包含A06，
导致这些模块无法继续显示已确认的图表和译名。此修复属于已授权图表修复。

采用独立只读投影，保留原整包matches_input和写入门槛，不改冻结core展示或科学规则。
仅A03/A04/A05可使用；A06/A07仍按整包当前来源，不投射旧矩阵或旧结论。
所有回执与图件继续经原read_record逐件核验，模块祖先闭包按归档run.parent_runs取得，
每个祖先的当前编号、run/result登记、父链、原active状态及最新人工意见均须适用。
首次人工通过仍沿原same_binding_after_first_approval；暂存／退回不能继续显示为适用。
模块原件、计划、当前来源任一变化就不采用，不从名称或数量相等判断同批。
对A05还要核原binding.a05_basis及归档分类／词典／快照，检查同A05后续独立展示范围和
核译决定。这些决定即使没有改变run/current/reviews，也不能被祖先闭包遗漏。
不能证明旧图仍适用就拒绝A05投影；不以当前默认词典重建旧图。A03/A04不受无关A05决定牵连。

先保留原整包资格，再为具体模块追加module_current，仅含该模块图件／表格／必要下载。
不把整包current改为true，不输出历史A06矩阵、构象、全局评分数量或全包下载。
页面明确“本模块来源未变，沿用已登记图表；不代表新A06已完成或科研批准”。
译名仍使用该原修订已登记核译，缺失阻断；GET不重画、不补译、不创建任务或Word。

## 方案比较及选择

等待新A06结束再重生成整包，会继续隐藏未改变的上游图；也不能据此代签新A06。
放宽整包matches_input会让旧A06结果混入当前批次，不采用。
本轮选择模块只读投影，恢复未变模块的可读性，同时保持整个批次的严格来源资格。

## 实施与核查

1. 契约先加模块投影字段；合成公开Workflow归档图表，随后仅改变无关下游，先复现缺图。
2. 新API辅助模块验证原回执和祖先闭包；复用原I/O、状态、人工决定读取，不重新定义科学状态。
3. Views只对三个当前模块接线，前端识别明确模块范围，不隐藏来源提示或扩大下载范围。
4. 测试祖先变化、暂存／退回、另一研究、原件损坏、译名缺失、错模块、历史与A06/A07拒绝；
   检查GET零研究写入、无图表生成、无任务，旧整包资格和旧回执字节保持。
5. 实际隔离病例核对Degree第二轮229/2064、全网1814/7692分开；原数量与译名无重算。
   窄宽屏、刷新、图件加载及下载核指纹，代码自审/回归/精确上传后再按运行条件部署。

当前真实科学worker与运行网页不得热换；原同runtime有活动任务的停服限制保持。
部署及实际用户入口仍需独立核验，不以隔离验证宣称当前页面已改变。

## 同批实际请求的内存核查与现有代码复用

实际A04读取的原scope保留645,211,902字节JSON原文、187,838,453字节marshal和23,102字节绑定事实。
独立诊断关闭循环GC后，退出仍保留833,073,457字节内容；正常生产不调整GC。
该次进程峰值1,740,541,952字节；当前科学worker与生产网页仍在并行，重复请求可能耗尽余量。
复测确认workspace与inbox存在重叠，但不将单次成功或观察到重叠当作全部MemoryError根因。

本轮选择新增HTTP读取适配，复用既有BoundedEvidence的流式首验、核验字节解析和有界JSON缓存，
默认64MiB，独立请求不共享；保留CheckpointReadEvidence已有白名单、继承、绑定与CP批读能力。
成功或异常退出均清空原文、解析、绑定、函数外观及继承包装器缓存，避免等待循环GC。
不修改冻结BoundedEvidence、read_evidence、checkpoint_json_read、worker或科学规则。
不扩大磁盘缓存/系统内存，不安装依赖，不用TTL或文件时间替代完整SHA。

直接清缓存仅降低请求结束后的保留，不能控制请求内峰值；仅串行会保留单请求的大缓存并延迟导航。
因此优先采用已存在的有界缓存与确定性释放，不新增锁或队列。超预算文档可重读重验；解析瞬时内存
仍与最大单件JSON及实际返回内容有关，64MiB仅是JSON缓存预算，不声称整个进程内存上限。
验证覆盖生产App及首页卡片入口、缓存淘汰/同字节重新解析、异常/manifest/末尾SHA失败、
根/线程隔离、实际病例峰值和残留、隔离浏览器7图与原文件下载。R原回归崩溃另记，不伪称全部通过。

HTTP仍按原UTF-8解码规则解析，拒绝UTF-16／32及BOM；直接采用json.loads(bytes)会扩大输入编码范围。
编码反例已先复现，因此仅在有界read_json原code的私有namespace中绑定显式UTF-8解析，
冻结函数及模块globals保持；不另抄读取、LRU或SHA实现。

新HTTP专项11项通过，包括释放、异常、末尾SHA、manifest、淘汰、独立返值、编码、线程与根隔离。
