# 全模块操作导航

用户认可A02操作顺序，要求每个模块增加符合自身用途的流程。当前模块标题下统一显示顺序卡：按钮按实际操作排列，突出后端建议位置，说明该步的目的；点击定位已有区域或进入同一研究的相关模块。建议位置不是完成率，不能代替页面原有状态、复核权限和人工决定。

## 页面操作顺序

| 模块 | 流程 |
|---|---|
| A00 研究登记 | 核对研究登记 → 疾病身份与范围 → 整体复核 → A01资料汇集（疾病资料在A02） |
| A01 方剂资料 | 检查已有来源 → 核对成分与靶点关系 → A02联合身份核查 → 整体复核 → A03交集 |
| A02 疾病资料 | 检查五库 → 保存疾病范围 → 程序核查身份 → 确认处理并生成结果 → 整体复核 → A03交集；沿用原导航与草稿保护 |
| A03 交集 | 核对两侧靶点与交集 → 成分关联排名 → 整体复核 → 分别查看A04网络、A05富集；两者可并行 |
| A03_SELECT 成分选择 | 核对身份与药味 → 明确纳入并保存 → 独立整体复核 → 对接准备 |
| A04 PPI | 检查输入及计算入口 → 身份例外 → 网络与两轮排名 → 整体复核 → 对接候选分组 → 成分名单 |
| A05 富集 | 确认KEGG展示范围 → GO/KEGG图表 → 确认版式 → 首位通路命中图 → 整体复核 → 报告进度；旧协议没有对应入口时不虚构确认动作 |
| A06_PREP 常规准备 | 已确认成分 → 候选受体 → 结构、位点与配体 → 准备范围和质控 → 整体复核 → A06结果；仅显示本页实际提供的准备入口 |
| A06_PREP 已关联批次 | 原核查来源 → 受体与位点证据 → 成分准备资料 → 原关联A06结果；不重复确认，不把扩展用途写成严格质控通过 |
| A06 结果 | 准备依据 → 评分矩阵与NA → 试算用途及核查（仅试算模式）→ 正式整体复核 → 按需出图/上传（有入口时）→ A07报告 |
| A07 报告 | 输入与提示 → 结论、数字与图表 → 下载核对两份报告 → 人工复核发布 → 查看已发布报告 |

点击A05范围或版式导航时仅展开原有核查区；未保存选择或正在应用时优先提示范围确认。成分保存步骤定位实际表单；首位命中图定位实际图区。已批准、未开始、运行、失败、失效和只读关联分别沿用已有事实提示。历史运行不新增操作导航。

## 实现边界

- `src/modulea/api/module_navigation.py`组合已有视图字段，`views.py`在准备关联等投影完成后调用；不重新计算科学结果，不改变状态或权限。
- `web/src/components/ModuleOperationGuide.tsx`显示步骤，`ModulePage.tsx`提供稳定定位区；A02原有专用导航保留。关联准备页通过`TrialPreparation`在标题后插入导航。
- 导航点击没有写请求：计算、来源整理、范围决定、名单保存、出图、整体复核继续使用原有按钮，均需用户明确操作。
- A01未标准化候选即使已有批准，也引导至A02联合核查。A05缺首位图按现有排名展示表与归档图片判断，不把空图片列表误当已经制作；无显著通路不补图。
- 科学参数、固定第24版模板、正式Word大纲、各研究输入及原批准不在本次修改范围内。
