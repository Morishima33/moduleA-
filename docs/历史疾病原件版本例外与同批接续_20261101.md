# 历史疾病原件版本例外与同批接续

本次接通一个有明确用户决定、仅用于单项流程测试的来源版本例外。GeneCards、OMIM旧原件可参与本次候选整理和后续技术验证，原版本字段仍为“未知”，原导出日期、完整性说明和文件字节保持。其他研究、正式研究、不同文件或不同方案不能继承该决定。

## 实际入口

在研究登记页打开“统一执行与续做”，进入“历史疾病原件的限定版本例外”，主动读取当前原件与已保存决定。首次使用须记录登记人、用户真实明确决定和说明，主动勾选后点击“记录限定例外并整理历史候选”。读取不联网、不执行，默认不勾；后台任务完成只发布待标准化候选，不批准身份或启动下游。

已记录的例外可展开查看，当前原件显示原版本、获取日期及指纹。A02页面显示本版限制、原候选条目和范围待处理情况，并指向统一执行条件，不使用旧分步上传、范围保存或标准化表单。历史候选没有标准化基因数量，不能用候选记录数代替。旧服务缺少能力声明时隐藏新入口。

## 独立协议与绑定

| 协议 | 职责 | 不改变的边界 |
|---|---|---|
| A02.historical_sources.1 | 保存本研究明确用户决定，绑定A00、方案、当前两份未知版本原件及同登记成功公共来源 | 不写模块人工复核，不补造数据库版本 |
| A02.historical_collection.1 | 复用原文并完整执行既有疾病解析、来源身份核对和候选整理 | handoff_blocked保持true；不启动A03 |
| A02.system_source_reuse.3 | 新明确批次沿真实候选来源链复用原件 | 不修改旧批快照、原获取记录或旧科学版本 |
| A02.system_normalization.4 | 按本批A01/HGNC及原范围规则重新标准化 | HGNC.resolve.3不变；身份未决仍阻断，无新增评分阈值 |

网页不传路径、URL、候选名单、虚构版本或通过标记。HTTP标准库只预检并排队；科学worker经公开Workflow核对后发布。原件、来源和科研意见获取前后核对，锁内追加不可变回执；任务中断后的孤立例外文件只可在同请求、同绑定时复用，禁止覆盖。实现快照、原文、参数及例外决定均进入研究追溯。

例外固定于原方案，后来追加草稿不替换已授权批次。用新方案开始新批不能沿用旧例外。回收站和明确人工暂停/退回禁止执行，历史原件和回执仍可只读核对。原system_acquisition.1、system_collection.1和前三版标准化行为保留，未获例外的未知版本仍阻断。

## 来源限制如何传递

候选与第四版标准化明确保存database_versions_complete=false、source_version_exception=true及source_limitations_zh。两份手动原件独立列入source_version_exceptions，保留库名、原版本、原日期、SHA及决定范围。完整追溯的plan_decisions.historical_disease_sources保留用户决定和原五库文件。

其他三库继续原有版本说明或响应快照规则。尤其OTP原件“接口未提供数据库发布版本；以响应快照固定”的描述保持，不能据此说已有可核实数据库发布号。页面和两份Word来源段均明确：仅本项流程测试，历史资料发布版本未知，不代表五库版本完整、完整检索或正式科研结论。
