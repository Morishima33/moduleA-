# 原生科学执行与 Windows 诊断

本批在独立 `codex/reliability-native` 实现。没有改动原 Windows 工程、研究数据或环境，没有启动真实 COPD 补算，没有修改冻结科学文件。旧 `A06.system_rescue.2` 继续原协议；原机接续步骤见[内存与接续记录](失败二版内存与安全接续_20261115.md)。

## 实现与边界

新增明确 `A06.platform_preparation.1 → A06.platform_qualified_preparation.1 → A06.platform_execution.1`。共用原 Workflow、研究登记、写锁、TaskManager、资源位与进程树，不增加存储或调度服务。新路径复用第二版身份、官方三维、Meeko、严格重对接及预测口袋判断；严格 RMSD 同时满足原 2 Å 和方案更严上限，Vina 参数来自已确认方案。结构准备仅归档事实，预测口袋不默认采用；明确完整选择后独立复验，形成待整体人工复核版本；评分还须原 review 入口实际通过。无自动批准、Word、身份猜测、坐标补位或静默换工具。

新平台的可复核路径依据原第二版准备完整校验器及原口袋采用规则，另设显式平台协议；不把旧 Windows 的补救、后补共晶参考、AlphaFold 或既有批准直接迁入。旧补救运行的原参数、实现、历史读取和恢复保持，跨平台科学数值等价性仍须对应平台实际对照审查。新协议只处理已固定并分别复核的 A06 输入，不改变候选范围。

逐来源、成分、受体和评分组合使用原研究索引登记的分对象检查点。已登记完整对象和稳定 NA 复用；中断残件保留，不把目录存在当成功。输入、批准、工具、Python、依赖、模型、源码、字体及实际执行参数绑定；工具或源码变化拒绝冒充同批接续。每个进程退出释放适配引用。新工具不使用 Windows 短名；仅准备包的 Vina **归档文件名**沿原校验布局保留 `.exe`，Mac 实际文件头必须是对应 Mach-O，并非调用 Windows 二进制。

网页 A06_PREP/A06 的“Windows / macOS 本机独立运行”按用户展开惰性读取，阶段、禁用原因和恢复模板均由后端提供。GET 不运行工具；POST 只能提供明确操作者、依据及口袋选择，不接收命令、工具路径或科学参数。任务使用 `-I -B` 解释器；内部 execute 须与运行中任务、父 PID、资源位和完整私有 payload 匹配，不能绕开队列直接并行。

## 安装与配置

原工具环境保持。为新平台另外准备 64 位 Python 3.12 科学环境，先安装仓库要求的工作流依赖，再明确固定科学包。此次 Apple Silicon 实际版本：RDKit 2024.9.6、Meeko 0.8.0、gemmi 0.7.1、NumPy 2.3.5、SciPy 1.18.1、PDBFixer 1.12.0、OpenMM 8.4.0、Pillow 13.0.0。Meeko/PDBFixer/OpenMM 必须使用此适配固定版本；其他版本也须在本机 profile 中明确并实际核对，禁止借版本号忽略文件 SHA。

- Vina 使用官方 [1.2.7 release](https://github.com/ccsb-scripps/AutoDock-Vina/releases/tag/v1.2.7) 中本系统/芯片的可执行文件。CLI 与 Python bindings 是不同安装项，见[官方安装说明](https://autodock-vina.readthedocs.io/en/latest/installation.html)；本适配调用 CLI。
- P2Rank 使用完整官方 [2.5 分发包](https://github.com/rdk/p2rank/releases/tag/2.5)，保留全部 bin/config/models。直接通过固定 Java 的 Main 类执行，沿官方启动脚本的 classpath、默认模型及 2048 MiB 堆，不依赖 Windows `.bat`。
- Java 此适配固定 19；此次用官方 [Temurin 19.0.2+7](https://github.com/adoptium/temurin19-binaries/releases/tag/jdk-19.0.2%2B7) 的 Mac aarch64 包，并核提供方 SHA。不是把机器默认 Java 随意替换。
- 有限修补复用冻结脚本原字节，固定 [PDBFixer 1.12](https://github.com/openmm/pdbfixer/releases/tag/v1.12)、OpenMM 8.4、CPU 单线程及原种子；不补缺失主链或放宽原坐标约束。某结构不通过时保留具体失败原因。
- 配置本机可用中文字体。Windows 可选择已安装微软雅黑，Mac 可选择宋体/黑体；配置和字体实际 SHA 进入新批绑定。字体、工具和个人路径不提交仓库。

先核官方分发与 SHA，再用本机 Python 执行下列命令。所有尖括号项替换成本机绝对路径；PowerShell 可分行用反引号，Mac shell 可分行用反斜杠，以下写为单行避免不同 shell 误解：

```text
python tools/make_native_profile.py --output <研究外新profile.json> --python <科学python> --vina <本机vina> --java <本机java> --p2rank <完整p2rank目录> --package rdkit=2024.9.6 --package meeko=0.8.0 --package gemmi=0.7.1 --package numpy=2.3.5 --package scipy=1.18.1 --package pdbfixer=1.12.0 --package openmm=8.4.0
```

profile 生成器不下载或安装软件，枚举实际完整 P2Rank 指纹，核本机版本和架构，拒绝覆盖已有 profile。将 [配置样例](../config/platform.example.toml)复制到不提交的 local.toml，填写数据根、研究外 runtime、科学 Python、tools_profile 和两种字体。Windows 使用 `modulea.cmd start`，Mac 使用 `./modulea.command start`；状态/停止和 `--no-browser` 详见既有[跨平台运行说明](Windows与macOS运行和迁移.md)。先运行平台预检，再从网页明确提交。预检可计算为真仍不代表已有研究已通过科学质控、原批可恢复或已科研验收。

## Windows 七项夹具问题

七项原错误都发生在共享 setUp 的目录创建，尚未进入业务；只有摘要，不能断言是普通长路径问题。现在基本场景用合理中文/空格目录，另有独立 **超过 320 字符**完整启停/重复启动/状态测试；Windows 同一绝对路径使用扩展形式，单组件保持系统合理范围，没有移除长路径覆盖。Mac 启动相关共 8 项通过。

```text
python tools/check_platform_paths.py --work-dir <独立可写测试父目录> --output <新诊断.json>
python -m unittest tests.modulea.test_platform_launcher -v
```

诊断同时记录原夹具原写法/同一路径扩展写法、超过320字符的两种形式、路径与单组件长度、Python架构、LongPathsEnabled只读值及 errno/winerror/filename。请返回 JSON 和完整 traceback，才可核定原机根因。脚本不改注册表或系统策略。Windows、Intel Mac 的实际启停/取消/本机科学全链仍待对应机器；PyPI/官方发布文件可获得不能计为平台实测通过。
