# 受体目录技术修订与同批资格评分

在原同批系统资格已归档后，新增明确的后台技术修订。只补执行原尝试中确有 `WinError 267`、且原口袋完整性和必要环境均通过的受体工具步骤。原输入字节、搜索盒、参数、候选次序和全矩阵保留；不重新联网、下载或预测。原来源失败、结构缺失或环境未解决仍按原科学规则保留。

修订前校验原资格和原准备的完整规范；受体工具输入必须与原预测输入字节一致。修订记录绑定原批次、原资格结果指纹、固定候选和本次实现快照。已完整归档的尝试重新核验后复用；中断只补未完成项。科学拒绝保留原日志，不作为通过。发表以 `A06.system_qualification_paths.1` 追加新运行，原运行与人工意见保留。索引保存后相同请求只读返回原修订。

评分仅接受当前修订资格，通过 `A06.system_scoring_paths.1` 复用冻结的 Vina 实现与第一姿势复验；全 NA 不评分，未成功项保留真实原因和空值。原 Vina、参数、单组资源、恢复行为和证据规范保持。源码保留独立的修订适配和所复用原执行器的字节证明。

两个任务只从既有本机预算任务入口调用，不增加 HTTP 或网页按钮。修订请求严格四字段：`batch_id`、`expected_preparation_run_id`、`expected_result_sha256`、`request_id`；评分请求沿用 `batch_id`、`expected_preparation_run_id`、`expected_scoring_run_id`。工具路径取自服务端配置。不允许客户端输入候选、分数、放宽质控、替换对象或写入人工复核。GET、重启或上传代码不会启动任务。

后续验收边界：修订和评分的新版本仍需接入冻结双报告和六格式导出。该阶段的隔离核查与代码上传不能替代原真实批次的新版执行、报告自检或统一用户验收。原批次和其后续程序运行期间不切换其正在使用的本机代码目录。
