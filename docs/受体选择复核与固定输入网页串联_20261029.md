# 受体选择、独立复核与固定输入网页串联

新版 A04 和 A06_PREP 页现可完成三项原后台操作：按本批方案生成受体名单、独立复核名单、保存 A06 对接固定输入。每项分别明确操作；名单生成和固定输入保存采用原后台任务，复核采用原独立决定接口。网页不计算或修改科学名单，不自动准备结构或执行评分。

## 操作与预期

1. 通过本研究的新方案 A04 网络后，打开 A04 页“本方案受体名单与对接固定输入”。页面显示 A04 实际绑定模式、目标数和 STRING 置信度。填写执行人、依据并主动确认后生成名单。
2. 查看实际完整名单、A/B标签、顺序和指标；选择通过、退回或暂存，填写实际复核人和意见，主动确认后仅保存名单复核。初始不选择“通过”，已有决定只作真实展示，修订需要新的明确决定。
3. 成分名单和受体名单分别通过、同源且方案一致后，到本页第三步或 A06_PREP 页填写登记人和依据，主动确认保存固定输入。成功显示实际成分数、受体数和全部组合数。此时结构准备、质控和评分都没有开始。

阻塞原因由只读资格接口逐项显示。空名单、未批准、不同交集、成分配置不匹配、回收站、研究任务正在运行或已有同批输入时，对应操作不能重复执行。撤回选择复核后，当前输入失效，历史文件保留。另存新草稿不替换旧网络绑定参数。

旧研究及原科学算法保持。新固定输入页移除了旧“一次确认自动对接”区域，避免将保存输入误当评分授权。实际准备和评分仍按各自明确入口及独立复核进行，统一一次确认流程尚待实现。

## 追溯

研究追溯JSON增加`plan_decisions`，完整列出`receptor_selections`、`selection_reviews`和`preparation_inputs`历史及各自文件记录。导出核验研究、版本和递归来源文件SHA-256，不把这些决定伪装成科学运行。CSV继续仅导出实际结果表；固定输入及组合范围保存在JSON。原件损坏时整个导出阻断。

## 实际验证

最终21项相关回归通过：真实HTTP、独立任务进程、选择复核撤回、输入失效、固定输入篡改阻断、成分任务、旧受体选择、追溯与新建兼容。关闭第三方site后接口、资格和完整追溯仍可读取，没有加载科学库。前阶段580次完整回归是提交基线，本阶段没有重复声称全量执行。

真实Chrome完成三次明确POST、两个后台任务：生成两项受体、明确保存隔离选择复核、保存两成分×两受体四组合输入。科学`current/runs`及模块`reviews`保持原样；只追加独立选择、选择决定和输入索引。生成和刷新不自动选择通过或提交下一步。最终1440/390px回读无整页横向滚动、自动POST和脚本错误，截图已查看。

导出与原归档45条CSV逐行一致，41个文件SHA核验通过；选择从原网络及方案重新计算一致，固定输入key及4组范围核验通过，manifest读取前后字节一致。验收证据在仓库外`开发与验收档案/audit_20261029/plan_selection_ui`，以`validation_summary.json`、`browser_check.json`、`final_readback.json`、`export_comparison.json`和上传回执为准。

使用合成上游及网络，不是正式疾病研究验收。独立本机预览19871未替换正式研究服务。首次测试的TypeScript兼容和浏览器切页等待问题已修正；初次记录保留，不计为最终通过。

下一大项是将固定输入接到既有新版结构准备任务，并整合统一运行计划、任务资源/恢复、新富集分类译名和双报告，最后统一端到端验收。
