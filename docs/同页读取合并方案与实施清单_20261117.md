# 同页读取合并方案与实施清单

## 已授权范围与设计

沿用户已经要求的页面提速、原状态算法和单请求完整核验方案实施；不改变科学筛选、
计算、人工关口、Word或真实worker。目标是减少同一页面对同一批大原件的重复核验。
单模块实测约39秒，现网页研究／模块／全局待办独立并发时约87秒，瓶颈仍在后端。

采用只读workspace请求返回原StudyView和ModuleView。每次HTTP新建局部Views实例，
仅本请求内复用一次原Workflow快照；返回容器分别复制，原方法和判断保持。
所有引用仍在本scope首次完整SHA并在发送前完整复验，不跨请求保存通过证明。
保留原study/module端点，文件下载、写入与计算不走workspace。
不采用跨请求TTL证明，也不减少附件核验或将未核状态当通过。

前端同页只发一次workspace读取，返回后同时更新研究和模块，保留旧响应丢弃及错误提示。
研究不存在仍整体404；有效研究的模块选择／历史运行错误放在module_error，保留原研究框架。
归档问题保留原StudyView.archive_ok=false与模块错误；退出完整核验失败整体拒绝，不能返回部分结果。
原“地址指定→下一步→首个模块”选择由后台沿同样顺序返回，历史run_id保持只读。
全局inbox在当次正在进行的workspace读取结束后再按原接口读取，数量与状态仍由后端返回。
未完成请求合并仍仅沿原client.pendingReads，完成即清除，POST仍清空。

## 实施顺序与文件

1. 更新 `src/modulea/api/AGENTS.md` 的只读GET契约；以虚构研究写真实HTTP失败测试。
   验收等值：workspace两部分与原独立Views读取得到的JSON一致；只构建一次原快照。
2. 新增 `api/workspace.py`，server只加路由和薄分派。保持原状态字段／错误和Host保护，
   验证未知／重复查询、错研究或历史运行、坏原件及返回前篡改不能发正常JSON。
3. 前端types/client/StudyPage接线，合并同页请求，待办延后读取。验证刷新、切页、
   历史只读、错误后恢复、无POST，以及请求完成后再次读取确实重新核验。
4. 相关回归及TypeScript／Vite构建；仅生成构建产物，不手改静态资源。
   用实际Python服务检查1440／390，按绘制后几何量取，无持续溢出或脚本错误。
5. 隔离真实病例只读量取整页耗时、请求顺序、首尾核验和研究／任务不变证据。
   这不是8780部署；生产仍受同runtime活动任务停服门槛约束。
6. 独立复审、精确文件提交、私有development非force更新并核远端提交／tree。
   技术证据、部署和用户科研验收分别记载，不以合成测试冒充真实流程完成。

## 设计自审

局部快照只保存于本次请求新建的对象，研究编号固定；离开scope即释放，不进入全局缓存。
复用的是原Workflow计算出的事实，不新建状态规则。返回前manifest及目录锚点和所有文件
仍全核；期间任何变动按原规则拒绝。任务进度仍为原TaskManager即时读取，
不声称研究manifest与任务数据库获得了跨存储事务快照。
需要用户新决定的科学规则不在本次实现范围。未通过验证的性能目标如实保留，不能宣称秒开。
