# 失败二版内存与安全接续

## 定位结论与边界

科学进程链为 TaskManager → resource_runner预算worker → tasks.system_receptor_rescue_v2 → `run_system_receptor_rescue_v2.py -I -S` → 公开Workflow二版execute → 科学compute/merge_pairs → 每区域执行/validate → Workflow登记检查点。其间来源绑定和原结果生产规范核验会进入 `read_evidence_scope`。HTTP请求范围是另一条链，已有HTTP二版提速没有覆盖该worker。

实际仓库发现：

1. `storage.verified_file/file_record` 为完整原件分配一份文件长度的 bytes；与JSON解析、其他常驻对象叠加时可能在此分配失败。
2. `ReadEvidence` 同范围保留全部JSON原文和marshal副本，函数namespace、reader回指还构成循环引用；原件核验本身无需同时保留所有内容。
3. 每次读取一个区域检查点，冻结读取器解析整份检查点清单；111个对象分别读取一次会解析12,321份JSON。该扫描本身没有复现与对象数相同幅度的长期payload持有，不能把重复解析直接称为已确证内存泄漏。

用户报告的原机MemoryError只确认失败位置。尚需原机完整堆栈、失败文件路径/长度、Python位数、进程/系统内存和检查点实测规模才能鉴定唯一根因。本批没有声称真实任务已恢复。

## 独立适配而非改写冻结文件

新增显式 `ModuleA.science_worker_io.1`，原二版协议、run/config、请求、科学实现、阈值和工具保持。原入口继续原行为；适配器只在新明确任务的函数私有namespace中复用原code，替换完整原件I/O与检查点读取。没有修改真实模块globals/sys.modules，未改 storage.py、workflow.py、contracts.py、read_evidence.py/read_archive.py 或两版补救科学/核心文件字节。

- 原件分块计算完整SHA/长度，同时核对句柄与路径身份，不能按mtime跳过内容。
- 有界JSON读取使用2MiB内容缓存，首次及退出全SHA、登记与路径核验保留；结束即释放循环引用。瞬时JSON解析仍与最大单件JSON大小有关，必需科学结果本身也仍占内存，不能宣称所有内存绝对恒定。
- 检查点身份头最多2048项，仅在每次完整SHA通过后使用；本对象payload/原尝试链和执行文件逐次复验，不缓存科学成功状态。其他对象变坏仍由完整SHA阻断。没有跨对象的指纹时效缓存。
- 同一失败二版、原请求和原run合法续做，不另建评分替代原26条。完整组及成功区域复用；部分组只补缺失/明确可重试区域；稳定失败与NA原因保留；未登记残件不算成功。
- 适配源码另存快照并登记 `worker_io_adaptations`，逐对象与最终发表前重核；run_file及人工reviews保持。适配改变需明确登记，不能伪造旧绑定。
- resume通过原TaskManager排队，使用原预算、同研究单任务、日志、出生身份与进程树取消。科学execute必须匹配原管理器活动任务、payload、父worker及计算位，不能用内部CLI绕开队列并发运行。

## 实测

Apple Silicon macOS，64位Python3.12.14；仓库外隔离合成资料，未运行真实Vina或COPD。GC保持启用，各模式独立进程。`tools/benchmark_rescue_memory.py`可在原机隔离目录重复运行。

| 场景 | 冻结路径Python峰值 | 有界适配Python峰值 | 其他事实 |
| --- | --- | --- | --- |
| 111份JSON，每份约256KiB | 57.88MiB | 4.20MiB | 内容缓存≤2MiB，首次与退出全SHA保留 |
| 444份相同大小JSON | 226.60MiB | 6.07MiB | RSS分别约280.36/45.52MiB；少量增长来自必要引用/路径元数据 |
| 单个64MiB二进制核验 | 64.01MiB | 2.02MiB | 返回同一完整SHA与长度 |
| 111对象逐个读取 | 0.96MiB | 2.03MiB | JSON解析12,321→221；仍完成12,321次清单SHA；未证明此小规模扫描更快 |

49项定向检查通过，覆盖同run恢复、完整组零重算、部分中断只补缺区、稳定失败、损坏、跨区域替换、工具/配置改变、适配快照篡改、目录残件、只读清点、禁止绕过队列与真实MODEL1字节。外部执行使用明确合成文件，原科学输出验证器实际运行；首次新增测试的夹具/导入错误日志保留，以batch-a-targeted-delivery-final.log为本批最终复验依据。

完整外壳回归首轮1246项：1093通过、23失败、90错误、40跳过。该轮在新增专项完成前启动；主要为字体、R、冻结Windows工具夹具和路径前提，全量不计通过。专项首次另有测试导入常量名称错误，已修正且保留首次日志。分类原始日志及后续修复在C批单列，不用定向结果覆盖它。

证据位于仓库外 `work/evidence-next/`：memory-*.json、batch-a-targeted-final.log、inventory-and-task.log、full-modulea-initial.log及其失败明细JSON；不将日志/截图/个人配置/研究原件提交仓库。
