# 报告原件恢复与用户批注保全

本次依据用户明确要求，修复历史简略版 Word 被添加批注后与原登记指纹不一致的问题，并完成真实案例验收前自检。保留用户批注，恢复精确原归档字节；不将修改后的 SHA 改签为原指纹，不重新计算、重建研究报告或代签科研复核。

## 恢复范围

`Workflow.restore_analysis_plan_report_archive` 接受明确请求和原备份字节，仅处理已登记 A07 结果中的 Word。备份必须与原结果中的 SHA 完全相同，待保全文档必须与本次请求的修改后 SHA 一致。正文、表格、图像和页眉页脚文字须一致，才可按“仅批注变化”处理；Word 自动加入的空脚注/尾注分隔符单独识别。正文发生变化时拒绝自动恢复并保留现有文档。

批注原字节和原备份先独立保存，随后登记不可变恢复计划，再在原目录原子恢复报告，最后登记完成回执。`current`、科研运行、结果索引、原报告 SHA 和 `reviews` 保持不变。新增计划与回执不是科研批准。

## 中断与并发保护

计划已登记但尚未恢复时，明确重试核验保全副本后继续。原报告已恢复但回执未写完时，重试只完成登记。完成回执须先核验，再进入研究索引；异常回执不登记，保全副本继续保留。若用户又修改了文档、备份不符、保全副本损坏或原运行登记改变，一律停止，不覆盖最新修改。GET、刷新和重启不会自动恢复。

## 批注版入口

原报告下载继续指向原字节。报告页“已归档报告”在双 Word 之外增加“用户批注版（保留N条批注）”下载。只读地址为 `/api/v1/studies/{sid}/analysis-plan/reports/{rid}/annotations/{repair_id}`，只接受本研究已登记完成回执，不接收路径覆盖；下载核验原报告、保全副本、批注与锚点。损坏沿用现有 `503 ARCHIVE_UNAVAILABLE`，不返回失配文件。

后续请在下载的批注副本中填写意见，原归档继续作为计算与追溯依据。新增批注不等于新的科学结果或报告内容修订。

## 验证与验收边界

合成研究覆盖指纹失败复现、精确恢复、原批注字节保全、错误备份、正文改变、额外字段、错运行、回收站、两个中断位置恢复、再次外部修改阻断、幂等、追溯和实际 HTTP 下载。旧报告两版网页及队列回归继续执行。

本次最终定向回归共14项通过，其中9项归档修复测试、3项两版报告与任务协议回归、2项原报告HTTP回归。最终日志为上述核查目录内 `repair_and_report_regression_final.log`；先前失败日志仅留作排查记录，不作为通过依据。

真实案例自检使用完整研究和原网页状态，不替换模块快照；核对归档、原科学数量/参数/评分、各模块页面、宽窄屏刷新和实际下载。证据保存在代码仓库外 `开发与验收档案/audit_20261107/annotated_report_repair`。

原简略版的历史图表拥挤、旧缺译和成分编号等呈现问题仍须如实记录。恢复原件和批注保全可以通过技术自检，不能据此称旧报告内容已经修订或用户终验已经通过。未经要求，本次不生成新的真实研究 Word。
