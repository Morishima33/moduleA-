# 新方案成分选择与网页验收

新版 A03_SELECT 现可按研究方案实际生成成分名单，协议为 `A03.plan_selection.1`。默认目标 15 项，可填 1—25 整数；排序读取方案中的不同交集靶点数或混合 Degree。完整保留边界并列，不足按实际，零交集不入选，不以低排名成分替换身份待补对象。旧固定前五及人工补充协议保留。

## 入口与预期结果

新版研究先完成并独立复核 A03，然后打开“A03 主候选确认”。“按本方案生成成分名单”显示方案目标、排序指标、原 A03 完整排名和阻塞项。原排名保留原顺序，归档后的正式名单单列，避免把两种排序混为一谈。

填写执行人、依据，主动勾选确认后点击生成。页面不预勾确认或复核通过，不将客户端自选名单、数量或指标传入科学任务。生成只追加待复核 A03_SELECT；仍从本页原复核栏独立确认是否允许下游使用，没有启动结构准备、Vina 或报告。

| 情况 | 预期 |
|---|---|
| 默认目标15但只有1项有交集 | 实际保存1项，并记录候选不足 |
| 目标2，第二位有2项并列 | 实际保存3项，完整保留并列 |
| 改用混合Degree | 按实际混合Degree重新选择，原A03数据不改变 |
| 无交集关系 | 保存0项有效空结果，不填入无交集对象 |
| 入选对象在当前身份草案中待补 | 明确拒绝发布，不换低排名补位 |
| 当前输入、批准或方案变化 | 旧请求拒绝，刷新后重新确认 |

目标1—25限制的是目标值，完整边界并列可能使实际数量超过25；原件、名单和实际范围都保留，不能静默截断。

## 归档与下游一致性

公开 Workflow 在写锁内固定方案、A03原结果和明确确认快照，后台复算全部名单和排序，发布前科学校验器再次比较。原 A03、A04和人工reviews保持。请求及方案、父结果逐件登记相对路径、大小与SHA-256；追溯JSON在本模块增加完整`execution_request`，导出前验证请求与实际运行关系，CSV仍来自同一实际结果。

新 A06 准备输入检查新成分配置的数量、指标与受体选择所绑定方案一致；不一致时先重新生成并复核名单，不能把不同方案的成分和受体拼接。旧选择版本保留原行为。本阶段接通成分名单，不等同完成结构身份、来源三维准备或评分授权。
