# 新版三库与疾病标准化衔接修复

在同一研究从实际三库原件推进到五库标准化的自检中，发现新A01.plan_publication.1已经形成完整标准化关系，而旧标准化入口仍按旧compound_targets原始表重算，导致KeyError，无法进入交集。此前仅分模块测试没有覆盖这个组合，原失败记录保留。

新增A02.plan_normalization_bridge.1入口适配，仅当当前A01为新版三库协议时启用。它先由真实生产A01验证器重核原件、参数、HGNC及全部表，再核对有效复核和相同映射；完整保留A01原结果，不把多源关系变成单库，也不重新筛选。疾病侧继续调用原冻结标准化算法、原范围和身份规则，生成新的待复核A02。映射变动须重新发布A01，批准撤回或输入变动均拒绝，不写新人工批准，不启动A03。旧A01路径保持。

网页仍使用A02原“核查基因身份→生成待复核结果”入口，不增加按钮或改前端；后台和接口资格已接入。新A01尚未复核时页面显示具体阻塞；发布任务说明只等待A02复核、原A01保持。当前分阶段入口仍有独立复核，完整一次确认自动版不因此宣称完成。
