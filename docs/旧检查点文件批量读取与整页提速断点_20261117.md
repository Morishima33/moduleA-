# 旧检查点文件批量读取与整页提速断点

## 原因和实现范围

本机真实只读剖析显示，冻结 `partial_recovery` 的原文件循环串行占约27秒。
原21个检查点共声明8485条文件引用、约1.56GB；其中单项5501条引用。
这是登记元数据分布，不是成功评分数，也不表示这些原件已通过科学放行。

新建 `ModuleA.checkpoint_json_read.1`，继承既有 InheritedReadEvidence。
只绑定本仓库实际 `partial_recovery` 函数对象，复用其原code、默认参数、closure和判断顺序。
其私有JSON副本中的 `files` 用兼容原list判断的迭代外观包装。
原函数完成运行选择、来源、人工意见、配置、previous链、成功不可覆盖判断，进入原
`for files` 时，才调用既有 `verify_all`。达到原规模条件时至多8线程逐件完整核验；
后续原逐件调用仍执行，只复用本请求已经完整核验的相同引用。

没有在检查点选择前扫描其files；原continue忽略的其他运行仍不读取其附属文件。
没有改变恢复名单、科学参数、错误关口、原函数globals、文件下载、写入口或科学worker。
退出仍逐件完整SHA，跨请求无通过证明缓存。跨根、跨线程、范围退出及非常规调用
回到原严格函数。生产JSON和首页／待办卡片的scope接新类，原继承读取范围文件保持。

## 自检

批量核验缺失先用原真实合成登记CP复现失败；生产App接线也先复现失败，再接线。
最终32项正常权限集成回归全部通过，247.967秒，包括新增10项、继承读取14项、
并发卡片／下载、旧A07真实合成HTTP及新平台只读GET。
日志之间有重叠，不把不同轮计数相加当作独立覆盖总数。

新增边界包括：原partial返回完全等值、实际多线程首次读取、首尾SHA数量／字节一致、
实际source_binding依赖链和原namespace保持、生产App接线、坏previous先拒绝、
其他运行CP附缺失文件仍被跳过、人工退回先拒绝、缺文件／同mtime损坏、读后篡改、
新请求重读、退出后包装器严格读取，以及复制Context到其他线程不共享证明。

## 真实观测与限制

隔离标准库进程只读真实A06观测39.105秒；首次及退出各14562件、2,317,440,407字节，
原current、reviews、run编号集合保持。前一版单模块约46秒；这是不同时间的观测，
不能外推为稳定比例，不能把单模块耗时当成整页耗时。

真实网页仍同时请求研究、模块和全局待办，整页两次观测约93秒／87秒，速度仍不足。
下一优先项是同一页研究与模块的单请求组装，沿原Workflow判断和同一首尾SHA范围，
避免独立请求反复核相同大附件；不能跨请求复用通过证明，也不能隐藏失效或待复核。
此处只是下一项设计方向，尚未实现合并接口或前端读取。

首次立即resize的390检查失败，日志保留为失败。后续记录显示初始scrollWidth为644，
等正常两个绘制帧后为390；1440稳定为1440。响应式实际绘制后无持续横溢，
无需为测试改产品样式。相应测量脚本已记录绘制前后宽度、失败截图与元素位置。
成功轮零写请求／脚本／HTTP错误，真实current/reviews/run编号及task编号集合保持。

隔离浏览器为临时端口／独立runtime，验证后关闭，不能冒充用户8780入口。
本批上传与实际部署分别记录；原SCI补算和常驻网页不热换、不重启。
完整真实补算、最终矩阵／图表／构象／下载及A07技术核对仍未完成。
不生成真实Word、不代签人工复核，不改变原16×15、26评分、Word批注和人工决定。
