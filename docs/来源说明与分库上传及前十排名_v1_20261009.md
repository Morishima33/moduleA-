# 来源说明、分库上传与前十排名

本轮依据用户明确确认的三项要求实施；不开展“主要成分”功能，不增加A03总数等式说明，不改候选对接规则。

## 来源名称与排名

A01当前成分与方剂靶点三库为TCMSP、HERB、BATMAN-TCM；A02当前疾病靶点五库为GeneCards、OMIM、TTD、PharmGKB、Open Targets Platform（OTP）。模块首次介绍列出名称，历史研究按实际来源方案保留DisGeNET等区别；库数不表示每库都有命中。

A03默认展示按不同交集靶点数降序的前十个成分；第十个并列完整保留，相同名次不人为打散。混合Degree等于交集靶点数加来源药味数，仅作参考；完整排名仍可分页查看，前十不自动成为对接候选。该排序不代表含量、疗效或结合强度。

## 大纲逐块确认项

1. A01/A02首次介绍列出本研究实际数据库及资料状态，后文允许三库/五库简称。
2. A01/A02按库提供格式说明、字段模板和上传留存入口，支持缺资料与获取失败后的补充。
3. A03默认展示前十及截断并列，保留完整排名；对接候选另行确认。

以上为本次用户已确认的实现要求；正式Word大纲仍待本块交付后由用户核对，不自行覆盖。

## 分库上传的使用与边界

在当前研究的A01或A02展开“数据库资料上传与更新”，选择对应数据库及格式，下载模板或包装说明，填写真实检索词、获取日期、版本与出处，选择文件并提交。每份文件上限16MiB；原文件及指纹单独留存，不覆盖历史。模板只有字段和包装规范，不能直接作为研究资料。

A01三库分别使用来源ZIP，必须覆盖登记处方全部药味。TCMSP保留原快照字段；HERB包含官方成分表、各药味工作簿、完整靶点命名表和已有关系详情；BATMAN-TCM只解析官方known_target_proteins，不引入预测表。完整三库和共同HGNC依据齐备后，再点击“整理已上传三库资料”生成新A01。单次上传不改变当前A01结果。

A02沿用已有解析：GeneCards支持官方CSV，OMIM支持.xlsx/基因表，TTD/PharmGKB/OTP支持既有采集器快照，各库也可使用明确字段的TSV。每次仅替换所选库，其他库原资料保留，生成待核查候选；范围和身份后续仍按原规则处理。GeneCards另记录加引号与导出完整性，未知信息不得伪造。

历史版本及回收站只读；上传绑定当前研究、A00、对应模块和上传清单版本，旧页面需刷新后重新提交。同一研究已有任务时阻止并发写入。解析失败如实报错，保留输入供任务重试，不显示为零命中。页面分别显示有资料、查询无命中、获取失败与未提供资料。上传和整理均不代签、不自动批准、不自动运行A03。

## 本轮核验

Windows独立环境完成外壳/API、科学上传与既有核心回归检查、前端构建及真实浏览器操作。核对三库原归档复算、A03完整排名与前十一致，原项目和既有核查快照指纹未变。技术通过不等于科学结果验收；新研究自动采集、范围/身份编辑等其余操作仍有待接入。
