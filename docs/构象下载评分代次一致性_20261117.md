# 构象下载评分代次一致性

补救构象接口原先把所有成功评分的来源说明固定写为“沿用评分不计为本轮新增”，
本轮真正新算出的分数也会收到该说明，验收ZIP沿用同一构造器而受到影响。
评分值和实际MODEL 1没有因此改变，但说明与矩阵中的评分代次可能不一致。

本次只修改API只读说明。对于第二版，读取科学包原已登记的
`reused_pair_keys`及`new_pair_keys`，核对组合唯一性、集合格式、重复、交叠、未知对象、
允许的状态和全部成功评分的代次覆盖。沿用集显示“沿用已核验评分，不计为本轮新增”，
新增集显示“本轮新增评分”。不能用累计`source_kind=rescue`或执行运行编号推断代次：
从未发表旧运行的完整检查点恢复的评分，在本轮已登记为沿用。
第一版没有上述集合，仍读取其原`original/rescue`类别，不升级历史协议。

details、context.json和验收ZIP共用该说明。context是按请求核验后生成的只读说明，
文字变更会改变其下载字节SHA；旧context链接以原SHA下载时明确拒绝，需要刷新。
原始执行、全部模式文件、MODEL 1字节、评分、参数、输入与历史研究文件不回写。
