## 1 为什么重构

原工作台功能齐全，但存在以下问题：
- 网页是单线程的，复核提交时同步跑计算，期间整个工作台没有响应；
- 每遇到新病例就复制一份脚本，研究编号和授权写进代码；
- 只能在一台 Windows 电脑上运行；
- AGENTS.md 和 README 是按日期追加的日志，新旧状态混在一起。

评估“全部推倒重来”和“在原基础上修改”之后，采用折中方案：**保留科学部分，重做外壳**。
- 科学内核里装着几十条用户逐条确认的规则，已批准结果都由它产生，重写的风险大、收益小，所以保留并冻结。
- 网页、编排和展示这一层问题最多，所以推倒重做。

## 2 这次做了什么

### 2.1 新架构外壳 `src/modulea/`

| 部分 | 做了什么 |
|---|---|
| 接口 `api/` | 新的本机 JSON 接口 `/api/v1`：研究列表、研究页、模块页、明细分页、文件下载、复核（含“保存并继续”和 A01+A02 一次提交）、回收站、待办、后台任务。服务是多线程的，沿用原有安全措施：只绑定本机、核对 Host 和 Origin、写操作需要令牌、只能下载归档索引里的文件 |
| 状态 `core/` | 状态仍只由原内核 `Workflow` 计算，新代码只做翻译，所以新旧工作台显示的状态完全一致 |
| 展示 `presenters/` | A00—A07 共 10 个模块各有一个展示适配，只读已归档结果，整理出关键数字、数量变化链、重点核对项、参数、韦恩图/PPI/富集/热图/报告数据 |
| 后台任务 `tasks/` | “保存并继续”改为在后台子进程执行，网页立即返回；任务可以看进度和日志、取消、重试；中断后不自动重跑 |
| 配置 `config.py` | 路径只在配置里出现：`config/local.toml`（不提交）或环境变量 |
| 开发工具 `devtools/` | 演示数据生成器：把某项研究的当前结果复制成一份可随意操作的演示研究 |

接口进程只用 Python 标准库，所以**任何电脑都能打开工作台、查看结果和复核**。后台科学计算需要科学依赖，用 `config/local.toml` 的 `science_python` 指定解释器。

### 2.2 新版前端 `web/`

用 React + TypeScript + Ant Design 按 UI 原型实现，包括：
- 首页：研究卡片、待办、回收站；
- 研究工作页：左侧分组导航、用途横幅；
- 模块页：本轮你只需核对这些、关键数字、数量变化链、各模块专属图，以及结果明细 / 参数与版本 / 来源与追溯三个页签；
- 右侧复核栏与后台任务面板。

构建产物已经放在 `src/modulea/static/` 并提交，使用者电脑上不需要安装 Node。

### 2.3 启动方式

| 入口 | 说明 |
|---|---|
| `start_v2.cmd`（Windows）、`start_v2.command`（macOS） | 新版工作台，默认 http://127.0.0.1:8780 |
| `start.cmd` | 原工作台，保持不变；运行模块、上传资料、范围决定、候选选择、对接方案、通路审核这些操作目前仍从这里进入 |

两个工作台读写同一套研究数据和同一个写锁，可以同时使用。

### 2.4 文档

- 根目录 `AGENTS.md` 改写为**当前有效约束的快照**：优先级、处理不确定问题的顺序、架构硬规则、现行科学决定摘要、当前状态、文件规则、代码规范、开发流程和停止条件。旧版 539 行原文完整保存在 `governance/AGENTS_历史全文_至20261008.md`，具体研究的授权以原文为准。
- `README.md` 写入完整的架构和设计；旧 README 保存在 `governance/README_历史全文_至20261008.md`。
- 各核心部分各有一份 `AGENTS.md`（`src/`、`src/modulea/`、`api/`、`presenters/`、`tasks/`、`web/`、`tests/`）。其中 `src/modulea/api/AGENTS.md` 是前后端接口契约。
- 新增本说明和 [Codex使用说明](Codex使用说明.md)。

### 2.5 清理

删除前先给原 main 打了标签 `legacy-v1-20261008`，下面这些都能从标签恢复：

- 11 个不再被引用的病例专用脚本（`docking_top10_altloc/recover`、`docking_expansion_publish`、`genecards_refill_*` 等）及其 2 个测试；
- 3195 个 `.pyc` 缓存、测试截图、`docs/_qa` 渲染检查材料、旧大纲审阅稿、上一版施工设计文档。

git 跟踪的文件从 13004 个减到约 9600 个。新增 `.gitignore`，以后缓存文件和个人配置不会再被提交。

**没有改动**：科学内核的规则、`studies/` 下的任何研究资料、已批准大纲 Word、`references/` 来源快照、`governance/` 档案。

## 3 验证结果

- 新外壳的 8 项契约测试通过。
- 科学内核测试：在装齐科学依赖的环境里，把本分支和改动前的 main 逐项对照，结果一致，没有新增失败。随删除模块一起移除了 8 项测试。双方都有 23 个报错和 5 个失败，原因是测试电脑（macOS）缺少 R、PyMOL 等环境，与本次改动无关。
- 两项真实研究（只读）的全部 20 个模块页都能打开，数字与项目记录一致。例如：
  - 过敏性鼻炎：交集 174，PPI 152 个节点、503 条边、两轮 39/13，对接 70 组中 47 组有效；
  - COPD：交集 208，对接 25 组，最负 −10.934。
- A07 两份 Word 下载后，与归档文件逐字节一致。热图与已批准的 v9 图一致。浏览器控制台无报错。
- 指定科学解释器后，后台“推进到下一关口”实际跑通，正确停在“请复核 A07”，没有代签。
- 两项真实研究的索引更新时间、复核数、运行数都没有变化。

## 4 目前的限制

1. **模块操作还在原网页**：运行模块、上传资料、A02 范围批量决定、A03_SELECT 选择、A06 结构方案确认、通路审核，新版工作台还没有入口。
2. **后台计算需要配置科学解释器**：未配置时，任务会失败并写明缺少哪个依赖、怎么配置；已有结果不受影响。
3. **历史遗留问题还在**（清单见 `src/AGENTS.md` 第 3 节）：
   - 代码里仍写着研究编号和授权；
   - `ppi_flow.py` 未传授权时会回退到 COPD 授权；
   - A07 有两套校验；
   - 存在多套重复实现；
   - 部分 Windows 路径写死；
   - 依赖版本没有锁定。
4. **模块页打开速度**：每次打开都会重新核验全部归档文件的指纹（这是有意的安全措施），文件多的模块（如 COPD 的 A07）需要 1—3 秒。

## 5 后续怎么做

按 [Codex使用说明](Codex使用说明.md) 第 3 节的顺序逐项推进，每项一个 PR：

1. 修复 `ppi_flow.py` 默认授权回退；
2. 统一 A07 校验；
3. 做复算护栏工具（必须在第 5、6 项之前完成）；
4. 模块操作接入新接口，做完后新版工作台即可完全替代原网页；
5. 历史授权移到研究包内的决定文件；
6. 解除通用代码对病例脚本的依赖，合并重复实现；
7. 复用键改为算法版本号、平台路径配置化、锁定依赖。

**开发方式**：Codex 会自动读取各级 `AGENTS.md`，下任务时说明任务和依据即可（模板见使用说明第 2 节）。遇到大纲和 `AGENTS.md` 都没有答案的科学问题，它应当停下来问你。PR 由你审核后合并。

**不在本次范围内、仍需你决定的下一阶段**：用正式 MeSH 资料完成一个正式病例。
