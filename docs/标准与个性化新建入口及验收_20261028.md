# 标准版与个性化版新建入口

本次完成 `ModuleA.plan_creation.1` 新模式建档：真实登记 → 统一方案校验 → NLM官方疾病身份与资料预检 → 一次明确确认 → 同研究A00和初始方案归档 → 页面回读与JSON导出。旧固定新建入口、独立参数预览和历史研究保持。

## 页面入口与操作

源码和生产网页已接入：首页点击“标准／个性化新建”，或进入 `#/new-plan-study`；旧新建窗口、参数预览页均提供入口。新建表单不会从旧研究、另一个窗口或参数预览静默继承值。

1. 填写方剂、药味、疾病中文名、MeSH首选词与编号、登记人，并明确选择正式研究或流程测试。
2. 选择标准版或个性化版。标准版沿用统一默认参数、15×15目标范围，参数只读；个性化版按原目录允许范围编辑，包括1—25整数的目标成分和受体数量。保留边界并列、不足按实际，目标数不等于最终可评分数。
3. 点击“核对登记、方案与资料”。服务端先校验字段，再实时核对NLM疾病身份，逐件检查当前配置数据目录的共享参考原件/清单和SHA-256。页面列出实际缺件，并把研究专属来源明确标为尚未提供；不存在“勾选即齐备”。
4. 阅读参数及资料缺口后，主动勾选“确认只建档，不启动分析”，再点击“确认建档并固定初始方案”。缺资料允许先建档以便后续按研究补齐，但不会启动计算。
5. 自动进入新研究A00。“本研究的初始方案与资料预检”显示初始模式、目标范围、方案编号/指纹、当前A00绑定的草稿。可下载绑定本研究的方案与建档预检JSON。创建时资料快照保留，后续上传不改写历史。

预检凭证有效期30分钟。登记或参数编辑会立即清除旧凭证和确认；创建前资料实际变化也须重新预检。重复确认、网络响应丢失后重试、服务重启或临时凭证丢失，均从原A00恢复同一初始研究；相同请求编号不能用于不同输入。后续新草稿或A00修订不回写原初始方案，重试建档不覆盖后续版本。

## 实现和边界

新入口调用原Workflow建档内核，初始方案在其同一写锁、同一次索引发布前追加并纳入A00文件指纹，不另造研究状态。预检只写运行目录中的短期凭证，研究内保留官方身份原响应、完整初始方案、参数指纹、资料快照及绑定关系。HTTP与核心建档功能经 `-I -S` 验证，仅需标准库；未修改 `workflow.py/storage.py/contracts.py`。

**本阶段完成建档与方案固定，不宣称自动分析全流程已经接通。** 当前新研究的A00人工复核不自动提交旧continue；手动continue、批量复核接续、后台continue也不会调用旧固定参数编排。A01/A04只接受新方案版本，A05新参数执行适配未完成时阻断旧替代。通过A00后可上传原件，但旧OB/DL获取和整理按钮禁用，接口和后台再次阻断；新方案已有科学函数的生产任务将在下一阶段接入。后续A00修订即使漏带扩展字段，初始方案仍锁定新协议身份，不回退到旧编排。

共享参考存在且指纹一致也不能证明本研究药味覆盖或三库/疾病来源完整。GeneCards和OMIM仍需在本研究A02来源区提交原件；TCMSP/HERB/BATMAN及其他疾病来源按本研究与方案后续绑定。现在不会自行复制旧研究资料或私自安装依赖来“补齐”。资料前置检查已提供，实际来源获取、执行适配和自动调度属于下一大项。
