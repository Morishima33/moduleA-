# 模块衔接与数据字典 v1.0

依据：已批准《ModuleA首版项目指导大纲_v1.0.docx》第4、5、7、11章。用户已授权助手落实模块衔接；未定科学参数不提前选择。本文件记录 P1 的实际接口，不代表全部科学模块已经实现。

## 1. 当前可用能力

P1 提供创建研究、A00 登记及修订、逐模块状态、人工复核、不可覆盖的运行记录、来源与输出校验、有效性判断和复用检查。正式研究目前只接入 A00。A01—A07 尚未实现计算，界面明确标注；测试研究只能用来检查模块交接，不产生科研结论。

下一阶段的模块应接入本框架，不能各自另建入口、另写状态文件或自行搜索上游“最新文件”。

## 2. 固定依赖关系

| 当前步骤 | 必须已复核通过的上游 |
|---|---|
| A00 研究登记 | 无 |

A06_PREP 仅将大纲规定的 A06 前置审核关口显式化，不增加科学分析。对接无需等待 A05；报告必须等待各必需分支完成审核。有效空结果可以复核，失败不能冒充有效空结果。

## 3. 文件与编号规则

沿用大纲目录，不创建 current、latest、final2 等并行事实目录。内部标识采用“类型前缀 + 32位 UUID”，如 study_…、run_…、artifact_…、review_…。名称不包含病名，不以排序赋予生物学优先级。研究名称作为可读字段保存，网页展示中文名称。

| 位置 | 内容与变更方式 |
|---|---|
| 根目录 start.cmd | 用户双击入口；只调用 src/start.ps1 |
| src | main.py 统一入口、web.py 网页、workflow.py 编排、contracts.py 契约、storage.py 留存 |
| studies/<study_id>/intake/<run_id>.json | 每版原始登记，不覆盖 |
| studies/<study_id>/runs/<module>/<run_id>/run.json | 固定输入、配置和上游版本，不覆盖 |
| 同次运行 result.json | 标准结果及文件索引，运行结束只提交一次 |
| 同次运行 <table_name>.csv | 可查看的明细表；表名为稳定英文标识 |
| 同次运行 anomalies.json、execution.json | 异常清单、执行起止与结果类型 |
| studies/<study_id>/reviews/<review_id>.json | 每次复核决定与历史关联，不覆盖 |
| studies/<study_id>/manifest.json | 唯一当前版本索引，原子替换 |
| raw、normalized、reports | 按大纲预留给后续真实资料、规范化结果和报告版本 |
| environments/.write.lock | 跨进程写入锁；锁文件存在不表示正在运行，也不是研究资料 |
| tests | 自动验收代码及明确命名的网页检查截图，测试研究使用系统临时目录 |

写入先形成同目录带唯一编号的 .tmp 文件，再原子发布；中断残留的 .tmp 不能作为成功结果。运行目录有文件也不代表可复用，必须通过索引、身份、指纹与复核检查。

## 4. 数据字典

### 运行上下文 run.json

| 字段 | 类型 | 含义 |
|---|---|---|
| schema_version | 字符串 | 本版为 1.0；不兼容版本拒绝静默读取 |
| study_id / run_id / module_id / artifact_id | 字符串 | 研究、运行、模块、产物的明确身份 |
| parent_runs | 对象 | 每个依赖模块对应的固定上游运行编号 |
| parent_review_ids | 对象 | 开始本次运行时生效的上游批准编号 |
| parent_artifact_ids | 字符串列表 | 上游产物身份 |
| inputs / config | 对象 | 本次明确输入与参数快照；不自行填写未知科学默认值 |
| input_hash / config_hash | SHA256字符串 | 输入及上游产物、参数的内容指纹 |
| code_version | SHA256字符串 | 本次新项目 src 内 Python 源码内容的组合指纹 |
| environment / environment_version | 对象 / SHA256字符串 | 实际 Python 和系统环境及指纹；科学工具接入后补充其版本 |
| created_at / reason | 字符串 | UTC 开始时间、首次运行或修订原因 |

code_version 当前只覆盖 Python 运行代码，不等同 Git 提交号；启动脚本和测试等交付文件另做文件清单。后续第三方科学工具的参数及版本必须进入各模块实际配置，不能认为 Python 版本已代表全部环境。

### 标准结果 result.json

共用身份、输入、配置、代码及环境指纹与 run.json 一致。另包括：

- outcome：success、empty 或 failed；不能用一个成功标志混淆科学空结果与执行错误。
- summary：结构化结果摘要；网页、表格与后续报告引用同一事实来源。
- tables：表名到记录列表的映射；本阶段适合小型结构化明细，CSV 同时导出。大型结构只放文件索引。
- anomalies：文字列表，记录异常和排除说明。
- files：所有被结果引用的归档文件，每项含相对 path、sha256、bytes、role。
- sources、figures：已实际归档的来源文件与图形文件索引；没有生成时为空，不生成假图。
- created_at、kind：结果时间、research 或 contract_test 的研究性质。

登记来源快照也参与结果校验。关联结构、图形或来源文件须先放入本研究包并形成文件索引，再提交；框架不替代具体模块的来源标注和科学内容核验。

### 复核记录

保存 study_id、run_id、artifact_id、config_hash、result_hash、review_id、decision、reviewer、note、previous_review_id、created_at。决定为 approved、rejected、pending，分别表示通过、退回、暂存。

复核人和意见必填；表单绑定实际看到的运行和上次复核编号。旧页面提交遇到新版本或新决定时拒绝覆盖，并要求刷新。

## 5. 统一调用接口

使用 Workflow(project_root)，正式科学模块通过 validators 参数登记自己的领域校验函数。所有模块都必须检查各自科学字段；通用契约校验不替代基因、结构、物种等专业核验。

| 接口 | 用途 |
|---|---|
| create(intake) | 新建正式研究并生成待复核 A00；本版 intake 包括方剂、药味、疾病、范围、登记人及 species=9606 |
| begin(study_id, module, inputs, config, reason) | 检查上游批准，固定其版本，建立新运行，返回完整运行上下文 |
| finish(study_id, run_id, summary, tables, anomalies, outcome, sources, figures, attachments) | 检查状态和文件，再发布完整结果；不自动批准 |
| review(study_id, run_id, decision, reviewer, note, expected_review) | 保存明确的人工决定，校验旧页面冲突 |
| revise_intake(study_id, intake, reason, expected_run) | 修订登记并创建新版本，原输入保留 |
| view(study_id) | 读取网页使用的统一状态和结果，不由网页另算状态 |
| reusable(study_id, module, inputs, config) | 检查本研究当前结果是否满足全部复用条件；不自动跨研究寻找缓存 |
| run / result / latest_review | 按明确身份读取归档输入、标准结果与批准记录 |

当 sources、figures、attachments 未提供时使用空列表；这不是认定必需科学资料齐备，领域校验仍须在适配阶段落实。新科学模块须提供 validator；未接入的模块不能在正式研究中提交占位分析。

## 6. 失效、并发与恢复

- 上游新版本、批准撤回或批准身份变化，使依赖该批准的既有下游失效；独立分支不受影响。原批准重新通过也不使旧下游悄悄恢复。
- 科学计算进行中若输入失效，其迟到结果不能发布为当前有效结果；实际计算执行器及中断诊断在对应模块接入时完善。
- 输入、配置、代码、环境、上游版本、输出指纹和批准状态都匹配时才允许复用。失败及校验不通过的运行不能复用。
- 结果未完整提交时显示“运行中或尚未完整提交”，不能认作成功。当前没有自动恢复后台科学任务，也不会自动重跑。
- manifest 只保存当前指针；历史运行和审核文件保留。采用进程间文件锁及原子索引更新，避免并发覆盖。
- 本地网页仅绑定 127.0.0.1；提交检查来源和随机表单令牌。下载只能指向归档索引中的文件。
- P1 不提供多人权限体系、不作电子签名认证；复核人由实际使用者填写。审批记录用于本工具过程追溯。

## 7. 本阶段与后续模块边界

本阶段完成工程衔接，不替代 A01—A07 的科学实现。上传及来源识别、数量变化链、表格搜索、自动采集、PPI/富集/对接、双报告导出与报告修订，在对应已批准阶段逐个接入。跨疾病方剂复用接口随方剂模块接入，不提前承诺当前已经可用。

未规定的科学问题实际出现时先查大纲；确实无答案才暂停受影响步骤向用户询问，不要求用户提前讨论全部假设问题。

GET /trash 显示回收站；POST /retention 只接受明确确认的 trash 或 restore 操作，沿用来源、表单令牌、写入锁及旧页面冲突检查。回收站内阻止新运行、结果提交、登记修订和复核，复用检查也不返回其结果；恢复后按原文件、原版本和原批准重新核验，既有资料与审核记录不删除。存在未完整提交的当前运行时暂不允许移入。

中文运行次序仅为按创建时间排列的阅读序号，不替换 run_id，也不代表算法或文档版本号。

### 来源与命名
- references/tcmsp_snapshot.tsv：原软件提取表逐字节副本，保留GBK编码和制表符。数据库发布版本未知，不作为官方最新版。
- references/tcmsp_snapshot.json：来源路径、指纹、字节数、编码、复制时间及限制；历史路径仅作出处说明，运行不读取旧目录。
- studies/<study_id>/raw/<run_id>/tcmsp_selected.json：该研究药味命中的全部筛选前原始字段，另附source_line定位源表记录。
- 同目录tcmsp_source.json：本次来源元信息；随研究包携带，不只引用共享快照。
- runs/A01/<run_id>：统一内核输出各结果CSV、anomalies.json、execution.json、run.json和result.json。无独立current副本。
- tests/test_components.py及tests/web_a01.png：验收代码及虚构研究界面截图；不是正式研究产物。

完整项目保留共享全表一次；每次研究携带实际使用的全部相关原始行，可用analyze重算本次结果，不必每个研究复制约80MB全库。新增其他药味查询仍需共享全表。来源指纹改变时不静默读取；公开再分发该来源的许可尚未核实，本次仅本机留存。

### A01标准结果
| 内部表名 | 主键或关系 | 用途 |
|---|---|---|
| components | compound_id=TCMSP MOLID | 通过预测筛选的成分、预测值、全部来源药味、不同人类基因数；三维身份尚未验证 |
| herb_components | herb + compound_id | 保存共享成分全部药味来源 |
| compound_targets | compound_id + uniprot + gene | 去重人类关系；species=9606；保留原表来源行号 |
| targets | uniprot + gene | 人类蛋白到源表基因符号映射，注明未在线更新且待专业复核 |
| herb_summary | herb | 原始行数、该药成分数及人类基因数，共享成员不可直接相加 |
| exclusions | source_line | 阈值排除、非人类、缺字段、身份/映射冲突及待核验原因 |

source_lines为分号连接的稳定源表行号。CSV保留内部字段名，网页显示中文；原值在raw中保存。不同成分编号不凭同名合并；同编号身份或预测值冲突单列。同一蛋白存在多基因冲突、缺映射或多值字段时不任取首项。明确的非人类与物种缺失使用不同原因。

去重关系数与原始人类证据行数分别输出；方剂基因集合按gene去重，蛋白映射仍保留。当前gene为源表标识，不冒称已完成最新HGNC标准化，后续A02/A03接入时仍需处理跨来源标识一致性。人工批准不修改或删除原表异常。

执行在统一写锁内核对A00批准、页面A00/A01版本和来源指纹；前置校验失败不创建A01结果。完整写入后才发布索引并等待复核。未实现自动恢复异常中断的科学任务；磁盘故障或强制终止需核查归档，不能据文件存在认定成功。

来源档案保存在raw/<run_id>/<database>.txt、.tsv或.json；扩展名按已声明格式确定，原始字节不变。raw/<run_id>/disease_sources.json为该次完整来源引用及范围决定清单。run.json保留启动输入和源字节指纹，因创建时尚未落盘的新来源引用以结果sources中的source_manifest档案为准；不覆盖run.json。未改变的来源继续引用原研究包内文件，无第二套current副本。

统一表：source_summary（五库存在/缺失及数量）、candidate_records（原始名称、稳定标识、评分、疾病条目、身份提示、范围标签、来源记录位置）、scope_groups（按来源内容指纹和疾病条目分组）、raw_union（未标准化名称并集）、raw_reference（原四库并集交OTP候选对照）、scope_history（范围决定、复核人、依据、UTC时间）。
record_id绑定数据库、原文件指纹及源记录位置；scope_id绑定数据库、原文件指纹、疾病名称与编号。文本表source_row为原行号，旧JSON为列表记录序号；OTP在线快照为“响应序号:页内行号”，多次返回用分号保留全部定位。分数缺失为明确空值，零分仍为零；通用TSV分数保留原文字，不跨库比较或自动转换阈值。

范围状态pending/direct/subtype/outside是专业意见。范围外原始记录仍保存，当前raw_union和raw_reference作为原始对照不随范围意见伪装成正式筛选。完整标准化与阈值获准后，另实现新配置和新运行，不改写候选历史。

Workflow.approved与review服务端检查summary.handoff_blocked；候选只允许暂存或退回。下游通过条件继续沿用原依赖表，A01通过不意味着A02通过。新增网页GET /disease分页查表、/disease-template字段模板；POST /disease-import、/disease-upload、/disease-otp、/disease-scope。所有写入检查来源、令牌、研究状态和当前A00/A02版本，回收站只读。上传单文件16MB，只有上传路由允许17MB请求；文件名不能作为任意保存路径。

现行预览可选字段 `box_proposal` 引用上述方案。读取时校验方案状态、研究与上游、准备包绑定、三个受体候选、参考配体和计算代码指纹；任何可执行标记均被拒绝。网页只读展示实际中心和尺寸，七项姿势规则与重对接比较默认折叠，不提供运行按钮。

## A06已批准规则与A06_PREP候选配置接口增补（2026-09-22）

`A06.box.authorization.1` 是对当前具体方案的用户授权记录。必须为 `status=user_approved`，绑定 `study_id`、三项 `parent_runs` 和 `A06.box.proposal.1` 文件完整指纹；`approved_items` 固定包含参考配体包络每侧5 Å、七项姿势规则、三次原配体重对接及top-1 RMSD≤2 Å诊断。该记录必须同时为 `redocking_execution_authorized=false` 和 `formal_docking_authorized=false`，避免把规则确认解释为运行许可。

`A06.preparation.config.1` 保存实际候选配置：固定Vina 1.2.7文件指纹，评分函数vina、exhaustiveness=8、num_modes=9、energy_range=3 kcal/mol、seed=1；三个受体分别保存中心、尺寸、参考配体和人工可读配置文件；七项姿势规则原样冻结；三次诊断和15组正式组合均为 `status=not_run`、空结果及 `execution_authorized=false`。任何分数或RMSD不得在准备阶段填0。

`A06.preparation.package.1` 是本轮集中复核的顶层清单，必需状态为 `draft_not_reviewable`、`published=false`、`execution_authorized=false`、`vina_invoked=false`。`counts` 必须同时保存三个盒子、七项规则、三份参考配体、三次诊断和15组正式计划的计划/完成数；当前完成数均为0。包内 `evidence` 包含授权、原准备包、RCSB化学组件原件、参考配体坐标、生成的SDF/PDBQT、盒子文件、运行环境和代码快照，展示前逐项校验。

参考配体使用RCSB化学组件键表、电荷和手性声明，不按原子距离猜键；重原子坐标必须按原子名与共晶坐标一一对应。理想坐标仅用于核对R/S声明，不替换实验姿势；补氢后复算化学式和总电荷。Meeko大环闭合 `G0` 是允许的计算伪原子，须显式记录且不得计入真实重原子数量或后续RMSD映射。

现行 `A06.preview.1` 可选字段 `box_authorization` 和 `preparation_package` 分别引用上述授权与候选包。配置形成后网页不再要求重复选择三项规则，只突出A03_SELECT网页总体签名和A06_PREP整体复核。候选包不得写入 `manifest.current`；完成整体复核后仍需建立明确的新执行授权，才能运行三次重对接，诊断通过后再决定是否启动15组正式对接。

## P4 A07双报告接口（2026-09-28）

`A07`必须读取同一研究中当前且已复核通过的A00—A06；任一上游版本、结果文件指纹或复核编号改变，旧A07不得继续作为当前交付。A03_SELECT用于主候选成分口径，但不替代A03总体复核。A06热图从其机器元数据明确指向的PNG读取，不按文件名猜测最新版。

顶层运行结果沿用通用`result.json`合同，`summary`固定保存共同结论草稿、结论复核状态、报告修订、详细/简略报告名和研究线索数；`tables`固定保存`key_counts`、`research_leads`、`limitations`、`report_files`和`version_bindings`。共同结论、关键数量和限制只生成一次，两份Word从同一结构化对象读取，禁止分别计算或手工抄写。

当前程序化模板版本为`A07.double_report.4`。专业详细版面向专业复核，临床简略版约两页；研究线索最多三条。未定义关联总分、疗效概率或通用结合能通过阈值。HSP90AA1未运行必须保留空值并说明质量控制原因，不得补零或解释为不能结合。

每次生成创建不可覆盖的`reports/report_rev_<id>/`，其中保存两份Word和`report_index.json`。研究`manifest.current.A07`只指向当前运行；旧修订继续保留以便追溯。当前A07在生成后为待人工复核，网页重点仅为共同结论、三条线索和限制边界；程序校验上游绑定、数字一致性、文件指纹和报告存在性。
