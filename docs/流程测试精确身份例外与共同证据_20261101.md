# 流程测试精确身份例外与共同证据

用户明确同意当前测试的身份问题清单暂不纳入主集合后，以独立 `ModuleA.identity_exception.1` 登记决定。版本未知例外、身份例外、结构核验和最终结果复核分别处理，不能相互代替。

本阶段通过公开 `Workflow.register_analysis_plan_identity_exception(study_id, request, evidence_bytes)` 接通后台；没有新增网页上传按钮或 HTTP 写入口。页面可阅读新结果中的限制与完整问题表，全部原文和决定进入现有完整追溯。独立新版本为 `A01.system_publication.2`、`A02.system_normalization.5`；旧版本及冻结 `HGNC.resolve.3`、状态存储内核保持。

登记精确绑定当前 A00、原方案、原 A01/A02、完整三库来源和原映射。请求包含实际用户决定、原 A01 完整问题清单指纹、A02 明确问题组编号和补充证据 SHA-256，不接受路径、任意网址、通过标记或自选科学参数。补充包必须原样保留原查询前缀，只能追加当前疾病问题实际精确编号对应的完整 Ensembl、HGNC、NCBI 官方查询集合；失败、缺响应、编号或物种不符、指纹不符均拒绝。补充原文为外部明确获取的原始响应，不把上传登记伪称为服务器新联网获取。

科学阶段重新验证三库原 ZIP、原参数、完整性、原 HGNC/NCBI 快照与共同补充证据。疾病侧按原直接范围规则独立诊断后，剩余问题组必须与本次明确清单一致；超出清单、遗漏或多选都不能发布。A01 同样只处理明确原问题组，不改变已匹配关系，不猜结构，不将家族拆分为单个基因。

登记只追加身份决定、证据、诊断和实现快照；不切换科学 current、不生成 reviews。新明确系统批次才绑定该决定及共同映射，不能修改旧批次的 initial_binding。之后 A01/A02 按各自独立新版本复算；原身份仍保留为未决，表中标记“本次测试明确不采用”，不把允许接续称作身份全部解决。三库不完整、人工暂停、回收站、新方案、新原件、其他研究或正式用途继续拒绝。

A01、A02 重点核对区明确显示本批限制；两份报告的来源说明同时列出例外及各侧问题组数，历史数据库版本限制继续保留。结构、PPI、富集、对接质控及最终人工结论复核仍按原规则执行。技术测试通过与真实研究接续、页面部署、用户验收分别报告。

实际系统批次的页面不显示不适用的旧人工阶段执行表单，结果和独立复核保留，后续指向“统一执行与续做”。已按原批规则暂缓的疾病范围继续标明未决、不纳入集合，不能误报为阻断本版已生成的交集；旧人工流程和实际阻断状态保持。大批来源在只读实例中复用已有有限并发、目录解析的完整 SHA 核验；每件原文件仍核对全部字节，不凭时间或大小跳过，科学与写入实例继续原逐件路径。已有成功页面不跨请求缓存。相关检查包括同大小同时间字节被改、缺失与越界均拒绝。

验证采用临时合成三库/五库，经生产 Workflow 和规范校验器执行到合法空交集及双报告；另核对真实当前研究和原件指纹。核查日志、原文、截图、研究数据和具体用户范围均留在仓库外，不上传 GitHub。
