# 疾病五库原件获取与断点恢复

新增 `A02.system_acquisition.1`，公开Workflow入口 `acquire_analysis_plan_system_disease_sources`按本研究实际A00系统校验证据获取疾病原件。此阶段完成后台基础层，尚无新HTTP/网页入口，不发布A02候选或正式疾病集合，不修改current/runs/reviews/手动资料暂存，也不伪造人工A00批准。

请求严格包含request_id（diseaseacqreq）、expected_a00、expected_plan_id、expected_input_hash、author、note、confirmed。固定当前登记、A02来源链、相关人工意见及预上传清单；运行中另存方案不替换原获取计划。输入或明确人工意见变化停止；缺确认、路径、疾病词、URL、passed等覆盖字段拒绝。网络期间不占全局研究写锁，同研究独立获取锁避免同时修改本次来源。

复用既有OTP、TTD、PharmGKB采集器及其MeSH精确词规则。GeneCards、OMIM仅采用本研究已有真实原件，不尝试绕过受限获取。当前同登记预上传优先；当前A02.collect.2原候选或A02.system_normalization.1/.2实际来源链的现代五库原件可核验复用，不扫描其他研究或历史择优。其他旧标准化协议仍须独立处理，不声称已全部兼容。

每个成功库原文先归档、按原metadata/parse_source/检索身份规则解析，再立即保存带SHA的恢复记录。整批写入前中断仍可恢复，失败只补失败库，成功原件保持；缺受限原件为missing、查询/核验失败为failed、合法完整零行为ready且parsed_records=0，不能混为零结果。补上传后原输入指纹变化，须新明确确认；同研究同A00的成功系统原件可以沿原检查点再次核验复用，保留旧请求和来源证据，不重新获取。损坏原件阻断，不用重下掩盖。完整同请求重复只复验，不再获取。

原始获取包、已有手动/候选来源、逐库恢复、实际失败及整批记录进入完整追溯JSON。失败能取得原响应时保留原文；既有采集器暴露source_trace时按原失败包装归档。此阶段不声称每个旧采集器内部所有未完成分页响应都已增加即时归档。
