# 系统三库原件接科学批次

新增 `A01.system_source_binding.1` 和 `A01.system_publication.1`，把明确获取且完整核验的原件接入实际科学批次。前者是独立科学输入，后者沿用原三库、TCMSP方案OB/DL、HGNC、完整性和身份算法。未替换旧上传协议，不伪造A00批准，不覆盖原件、科学运行或人工复核。

公开Workflow方法 `bind_analysis_plan_system_a01_sources`严格接收request_id、expected_acquisition_request_id、expected_record_sha256、expected_input_hash、author、note、confirmed。只接受本研究原登记、原方案、最新完整采集记录；参数已另存、登记或明确人工意见变化时拒绝。调用前后原ZIP逐件复验；实际解包与原解析器生成产物归入独立目录，另存原采集确认、实际方案、SHA和实现来源。单独指针current_system_component_sources与旧current_component_uploads分开，绑定不发布科学运行。

科学校验从原ZIP重新解包并按原解析规则重建，每个实际文件逐字节相同才采用；即使篡改解析文件后重算SHA，仍拒绝。额外未登记文件同样拒绝。批次明确记录component_source_protocol和真实新来源，initial_binding仍保留当时实际旧staging_file，可为null，不把系统获取伪装成人工上传。旧无系统来源指针的请求快照和批次规则保持。运行中新草稿不改变原批；新来源被替换后旧批拒绝执行。

新A01规范验证器在生产分派中独立登记，实际原件链复算后调用冻结plan_flow.facts；调用方lambda或客户端通过标记不能绕过。系统父依赖仍使用真实规范回执，parent_review_ids为空，不授予旧approved。新A01可继续到既有系统A02、交集和A07双报告，旧科学版本继续原校验器。追溯包含完整系统来源绑定及原采集和逐件SHA，标准库读取不执行科学解析。
