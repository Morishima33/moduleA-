# 系统批次授权与A01/A03真实交接

本阶段为最终一次确认自动执行建立独立系统授权基础，协议`ModuleA.system_execution.1`。当前只实现A01、A03两个内部阶段，整套自动按钮仍关闭，没有新网页操作入口。不得将这一基础层称为全流程自动版完成。

公开Workflow方法`start_analysis_plan_system_batch`一次保存明确请求、原方案、当前登记、三库实际原件、HGNC及补充依据。`execute_analysis_plan_system_stage`只允许已接通阶段，后台先实际执行生产规范验证，再以真实`parent_validation_records`交接。运行记录另存`execution_protocol`、`execution_authority`和`batch_file`，人工`parent_review_ids`为空；科学配置和计算仍为原新方案版本。

新生成的A01不写人工审核、`approved`仍为false，但可由实际规范回执进入系统A03。原`approved/latest_review`语义和旧工作流不改；来源有明确人工暂存、退回、撤回，仍然否决交接，再生成一致性通过回执也不能覆盖。完整上游、结果、来源和批准变动均重新核对，失败不能变成功。

运行中增加方案草稿不替换已确认批次。A01实际计算在锁外，发布前锁内重核；原件替换、当前指针变化或回收站均拒绝。批次及成功阶段幂等，不重复科学计算；失败追加真实异常与已产生的未发布文件指纹，原结果和历史保留。调用者提供的假validator也不能绕过实际生产规范校验。批次、阶段回执、失败诊断、派生请求和运行授权完整进入JSON追溯，表数据按原CSV导出。
