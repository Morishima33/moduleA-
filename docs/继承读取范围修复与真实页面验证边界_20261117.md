# 继承读取范围修复与真实页面验证边界

## 问题及范围

新平台执行和救援报告加入继承链后，部分只读 `_active` 委托又落回原始模块的文件读取。
上一批 `read_call` 桥接避免了同请求重复构造绑定，但未覆盖深层 `super()`，真实病例仍很慢。
只读诊断发现原始 `storage.verified_file` 重复调用6177次；这个观察不代表科学评分失败。

本批新建 `ModuleA.inherited_json_read.1` 范围，继承现有 RescueReadEvidence。
只对本仓库五层类实际定义的 `_active` 方法对象分派私有 `super` 外观，方法体仍复用原
code、默认参数与closure；其他属性和方法、未知函数以及所有写方法保持原分派。
HTTP JSON入口及首页／待办的研究卡片组装采用本范围。

范围必须属于当前线程、数据根及ContextVar。退出后、其他根或复制到其他线程的上下文
不能继续使用证明。文件下载、正常写入、后台科学计算均不采用本范围。
未修改冻结 read_evidence、rescue_read_evidence、workflow、storage、科学算法或实际补算的源码。

## 验证依据

继承链诊断及生产JSON接线各自先复现16次原storage读取，修复后在同范围内不再落回原读取。
边界验证包括同路径不同SHA、恢复mtime的同长度篡改、研究manifest改变、跨线程／根、
退出后继续调用、未知／写方法保持原样。生产HTTP分派另核页面与原直接读取等值，
并在返回前损坏原件时返回503，不能发送正常页面JSON。
全部读取仍首次逐件完整SHA，返回前再次逐件完整SHA；没有跨请求TTL或文件时间替代。

本机隔离进程只读当前真实A06，观测从上一版81.738秒降为46.164秒；后一版核14562件引用、
2,317,440,407字节，首验与退出复验的数量／字节均相同。带cProfile的另一轮为55.753秒。
这些是同机观测，后台计算仍追加检查点，不能解释为严格配对基准或固定提速比例。
当前版本、人工复核及运行编号集合保持；隔离runtime无真实任务状态，未启动科学工具。

生产路由／原JSON入口、目录联接、原A07三版和新平台执行定向回归53项通过（515.513秒）。
卡片与并发读取相关20项执行，19项通过、1项跳过；新HTTP退出篡改及双研究线程范围检查
另有实际通过日志。不同日志存在重叠，不相加冒充独立测试总数。
初次受限环境回归36项有1个HTTP权限错误和2项目录联接跳过，不能称该轮通过；
随后正常权限回归实际验证HTTP及目录联接并通过，未改权限或跳过保护。

新代码临时端口的真实病例浏览器观测：A06首次可见约92.568秒，1440／390宽度无横溢，
零脚本错误、零HTTP错误、零写请求，真实current／reviews／run编号及任务编号集合保持。
这包含网页同时发出的研究／模块／全局待办读取，故不把46秒单模块测量称为整页加载速度。
临时端口仅用于本轮验证，已关闭；不是用户应使用的服务入口，也没有完成实际8780验收。
