# 网页进入与模块切换提速

## 2026-11-11 当前系统批次读取补充

当前玉屏风散—COPD 在正式 8780 入口实测，研究信息从 17.92 秒降到 10.26 秒，A03_SELECT 成分确认模块从 55.44 秒降到 10.92 秒。两份响应的全部内容与修改前相同。这是同机单次前后对照，实际时间随系统负载和磁盘缓存变化。

从实际网页入口独立打开时，导航、模块与全局待办并发读取。1440/390 像素下模块可见时间分别为 32.75/33.75 秒。页签切换、刷新、selected.csv 实际下载与指纹比对通过，写请求和脚本错误均为零。完整页面仍有等待，不能把单接口的 10.92 秒当作整页打开时间。

性能追踪发现成分确认区重新创建普通 Workflow，重复核验已由模块页面检查过的来源和依赖。当前读取沿已有只读实例与单请求证据范围，独立读取时建立本次 handoff 缓存，完整组装后再次逐件检查 SHA。执行任务的 POST 继续调用原 Workflow 和预检。

同一请求内已解析 JSON 只编码一次，每次调用仍返回独立对象。缓存随请求退出失效，文件变化和研究登记变化照常阻断。读取、并发隔离、篡改及成分选择定向回归共 53 项，52 项通过，1 项 Windows 原生符号链接权限限制跳过。

后续可继续合并研究导航与当前模块读取，减少进入项目时并行重复扫描；将历史记录和大型明细延后到用户展开时读取。两项仍属待实施方向。现行整套状态与报告依赖核验仍有约十秒量级的读取开销。当前证据位于仓库外 开发与验收档案/audit_20261111/loading_performance。

用户明确允许仅修改网页性能部分，科研算法、参数、结果与审核规则保持。优化的是进入项目及切换模块的等待，不是分子对接计算本身。

## 原因与修改

- 页面启动时，任务发现会立即刷新一次，无活动任务的定时器又再刷新一次。研究和模块归档重复请求，全局待办也并发读取全部项目。现在首次进入只读取一次；切回窗口仍刷新，真实任务结束仍刷新并补一次落盘核对。
- 大型附件原先整件读入内存后计算指纹，现在使用分块SHA-256。JSON解析直接使用本次已核验的字节，不再另开文件重读。文件身份、字节数、完整内容摘要、读取期间变化和目录边界检查保留；不以mtime代替摘要。
- 大批小附件按组调度，仍最多8个读取线程，全部核验完成才返回；失败传播保持。
- 共享中的同版本状态仍向每个请求返回独立对象。归档容器使用同进程内存编解码复制，保留容器别名，非归档Python对象回退原deepcopy；不读取外部序列化字节，不落盘，不新增跨请求TTL缓存。

科学内核及写入Workflow未修改；复核、下载、结果及历史版本的身份和内容核验边界保持。构建产物随本次源码同步，并保留上一版静态资源供已经打开的页面继续读取。

## 实测与验证

本机同一研究、同一宽屏浏览器，更新前与正式服务更新后的一次对照：

| 操作 | 修改前 | 修改后 |
|---|---:|---:|
| 进入项目至A01可见 | 9.18秒 | 5.52秒 |
| 切换A02至页面可见 | 4.54秒 | 3.68秒 |
| 初次进入至请求完成 | 21.67秒 | 10.61秒 |
| 初次进入全局待办请求 | 3次 | 1次 |

以上不是多机器平均值，受资料规模、磁盘缓存和系统负载影响，不承诺固定秒数。网页仍保留必要的真实归档核验。

研究摘要、A01及A02三个真实接口与修改前返回内容完全相同。只读性能测试覆盖完整文件末字节篡改、恢复mtime、JSON重用前核验、分组末项失败、请求副本隔离、内部别名、非归档对象回退、并发与版本保护；Windows无符号链接创建权限的一项明确跳过。API检查覆盖全部模块、复核与过期保护、安全、分页及回收站。

浏览器验证实际打开及切换、无任务不重复刷新、窗口聚焦刷新、任务结束和延迟核对、390像素窄屏；未发送科研写请求，无页面错误。第24版28份冻结文件指纹一致。源码与实际结果的详细证据位于仓库外 `开发与验收档案/audit_20261023/web_performance/`。
