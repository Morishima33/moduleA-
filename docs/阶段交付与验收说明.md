## 阶段报告固定格式

| 项目 | 报告要求 |
|---|---|
| 完成内容 | 说明实际增加或修复的行为，以及本阶段不包含什么 |
| 使用状态 | 明确代码已上传、当前网页是否已加载、是否有可操作入口 |
| 用户验收 | 给出可直接打开的入口、按顺序操作的步骤，不要求用户自行排查技术问题 |
| 预期结果 | 每个动作对应可看到的数值、状态、文件或错误提示，区分虚构样例与真实研究 |
| 技术证据 | 由助手完成测试、版本核验和必要截图检查，记录实际结果及证据位置 |
| 遗留和下一步 | 未部署、未验证及未通过项如实列出，说明下一阶段具体动作 |

“技术测试通过”不能代替“网页可以使用”或“真实研究验证通过”。没有页面的后台基础阶段，明确没有用户操作验收入口；规则核对和技术证据交付后，保留集成验收待办。

每个已交付阶段都必须同时留下：原始输入或来源文件、参数及方案版本、处理/筛选规则、实际运行编号、父版本和复核关系、输出表/图/报告、文件大小与SHA-256。用户可在研究页或接口中查看阶段摘要，并下载完整JSON追溯包和CSV数据；下载前服务端会重新核对文件指纹。导出内容必须绑定同一研究和同一当前版本，不能把旧批次或其他研究拼入。

## 后续可见阶段的交付标准

每次提供实际地址及至少一组操作和预期结果。例如：打开创建窗口，选择个性化，修改参数后保存；重新打开应恢复相同数值，执行记录和报告采用相同数值。标准版仍使用默认方案；两个项目的文件与结果互不覆盖。

自动运行、异常恢复、出图及报告阶段同样提供操作清单，说明哪里看进度、哪些异常会继续或暂停、文件在哪里下载。验收使用隔离项目，不能把已有正式研究当成试验输入直接重算。
