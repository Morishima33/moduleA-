# Module A 页面性能优化（2026-10-15）

本轮仅优化新架构的只读I/O；科学内核、状态规则、评分、双报告模板及人工批准保持原样。

原因：原状态读取每批近6000次文件核验，反复展开Windows路径；页面的研究、待办、模块请求又同时重复读取。A06试算展示再次逐个核验整批附件，图片及下载入口也重复执行旧读取路径。

改动：只读实例在一个请求内复用安全目录解析和JSON解析；每次仍逐文件读取并核验SHA-256，不用文件时间替代内容核验。大批附件最多8个线程读取，等全部核验通过再返回。相同研究和manifest版本的同时读取共用正在执行的完整状态核验，每个请求取得独立副本；完成即移除，无跨请求状态TTL缓存。复核、任务及后台科学计算继续使用原Workflow。

验证：旧服务与最终优化服务的研究列表、待办、研究状态、A07和A06五项JSON逐字节一致。实际浏览器冷开至复核栏可见（秒）：

| 页面 | 优化前 | 优化后 |
|---|---:|---:|
| A07 | 22.88 | 9.06 |
| A06 | 24.50 | 10.22 |

本机同一研究的单轮对照，含浏览器实际请求和页面渲染；不代表不同机器、资料规模或磁盘负载下的固定速度。详细接口耗时见核查证据。

测试：前一轮37项回归完成（1项符号链接测试因Windows无创建权限跳过）；最终相关31项完成（同一项跳过），覆盖文件篡改、恢复mtime、附件缺失、路径越界、并发失败、接口状态、安全和试算边界。没有执行真实对接或新疾病计算。

代码：`core/read_archive.py`、`core/kernel.py`、`api/views.py`、`api/trial_view.py`；接口字段未变。

核查证据存于仓库外 `开发与验收档案/audit_20261015/page_performance/`：`profile-before.txt`、`http-release.json`、`browser-release.json`、`tests-final.log`、`tests-release.log`、`production-proof.json`、`github-upload-proof.json`。
