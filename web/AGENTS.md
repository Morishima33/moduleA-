# web/ — 前端开发规则（给后续开发代理）

开始前先读取项目根目录的 `AGENTS.md`、`README.md` 与本文件；项目级规则（先查大纲、未定问题先询问、文件命名与存放、注释要求）同样适用于前端。

## 1 以接口契约为准

- 唯一依据是 `src/modulea/api/AGENTS.md`。字段、状态码、错误码、令牌和并发规则都以它为准。
- **改接口先改契约**：需要新字段或新端点时，先修改契约文件并由后端实现，再改 `src/api/types.ts` 与页面。前端不得自造字段、不得猜测未登记的端点。
- 发现接口缺字段或行为与契约不符时，不在前端“补算”，记录下来交给后端处理。

## 2 不在前端推算状态与科学结果

- 模块状态只看 `state.code` / `state.label_zh`；能否复核只看 `review.can_review`、`review.allowed_decisions`、`review.already_approved`；能否继续只看 `review.continue.available`。
- 不在前端计算交集、阈值、评分、通过与否、下游影响；数字与说明一律显示接口给出的值（`text`、`*_zh`）。
- 允许的只是“显示格式化”（时间、文件大小、长小数缩写、p 值上标），原值须可悬停查看或下载核对。
- 热图配色规则固定：数值越负红色越深、越不负蓝色越深，红到蓝平滑过渡；单个缺失格白底“NA”虚线边，不填 0、不填灰；不得设置通用结合能阈值。

## 3 写操作

- 所有写请求经 `src/api/client.ts`，自动携带 `X-ModuleA-Token`；令牌失效时客户端会重新取令牌重试一次。
- 复核必须带 `run_id` 与 `expected_review_id`；管理操作带 `expected_action_id`。收到 409 `STALE_VERSION` 时提示“状态已更新”并重新加载，不自动重复提交。
- 程序不得代签任何模块：不能在用户未操作时提交复核，不能预选“通过”。

## 4 构建产物

- `npm run build` 输出到 `../src/modulea/static/`（会先清空）。该目录只放构建产物，不手工编辑。
- `node_modules/`、`dist/` 不提交；不要把依赖复制进 static。
- 改完前端必须重新构建，并用 Python 服务（Host 为 `127.0.0.1:<端口>`）实际打开验证，确认无控制台错误。

## 5 样式约定

- 背景 `#F2F4F5`；卡片白底、1px `#DCE1E5`、圆角 12；主色 `#0F5E6E`。状态配色集中在 `src/lib/theme.ts`（取自原型《模块状态样式一览》），不要在组件里另写一套。
- 使用 Ant Design 组件；主题与中文语言包在 `src/main.tsx` 统一设置。
- 窄屏（< 992px）导航改为抽屉，复核栏堆叠在“重点核对”之后；任何宽度都不得出现整页横向滚动（宽表格与热图只在自身容器内滚动）。
- 面向用户的文字全部用中文。

## 6 不加载外部资源

- 服务端 CSP 只允许同源脚本：不得引入 CDN、外部字体（例如 Google Fonts）、统计脚本或远程图片；字体用系统中文字体栈。
- 不使用 `eval`、`new Function`、内联 `<script>`。新增依赖前确认其运行时不需要以上能力。

## 7 代码注释

- 每个文件开头用中文说明用途；每个组件/函数上方用中文说明做什么；关键语句旁加简短中文注释，面向代码初学者。
- 注释中不得出现令牌、个人路径等敏感信息。
